# meeting_notes — Examples

## 1. 붙여넣은 메모 → 정리된 노트 (success)

**Input**
```json
{
  "path": "notes/2026-07-27-weekly.md",
  "notes": "주간회의. 1분기 예산 1200만원으로 확정함. 마케팅 40%. 태수님이 예산안 공유하기로. 2분기 계획은 이사회 승인 필요한데 일정 미정.",
  "content": "# 2026-07-27 주간회의\n\n## 결정사항\n- 1분기 예산 1,200만원 확정 (마케팅 40%)\n\n## 할 일\n- [ ] 예산안 공유 — 태수\n\n## 미해결 질문\n- 2분기 계획 이사회 승인 일정 미정\n"
}
```
**Output**
```json
{ "success": true, "path": "notes/2026-07-27-weekly.md", "bytes": 178 }
```

메모에 담당자가 적힌 항목만 담당자가 채워졌고, 기한은 어디에도 없었으므로
비워 두었다 — 추측해서 채우지 않는다.

## 2. 결정사항이 없는 회의 (success, 정직한 빈 섹션)

**Input**
```json
{
  "path": "notes/2026-07-28-sync.md",
  "notes": "짧은 싱크. 다들 진행 상황 공유만 하고 끝.",
  "content": "# 2026-07-28 싱크\n\n## 결정사항\n- 결정된 사항 없음\n\n## 할 일\n- 없음\n\n## 미해결 질문\n- 없음\n"
}
```
**Output**
```json
{ "success": true, "path": "notes/2026-07-28-sync.md", "bytes": 96 }
```

없는 결정을 만들어 내는 대신 "결정된 사항 없음"을 그대로 적는다.

## 3. 기존 노트를 덮어쓰는 경우 (변경 제안)

이미 있는 파일을 대상으로 하면 ChangeGovernor가 변경 제안으로 돌린다. 디스크는
승인 전까지 바뀌지 않으며, 검토함(Review Center)에서 승인해야 적용된다.
