# v11.5.2 — Tight Ship (design plan)

Three audits ran against the settled v11.5.1 tree: AUDIT-A (Rust↔Python
duplication map), AUDIT-B (dead code and no-longer-needed tests, arc-level
verified against the 100% line+branch gate), AUDIT-C (live front-door parity:
Rust gateway vs. direct Python worker, 192-endpoint sweep plus targeted
batteries). This plan is the design synthesis; implementation is delegated in
two waves. Nothing in this release changes the migration's final form: Python
remains the AI Worker and the sole client-facing implementation of every
`/api/*` route; the Rust surface stays pinned by parity goldens.

## Audit verdicts that shape the release

1. **Cross-boundary duplication is all by design.** Every Rust module's Python
   twin either serves a live route in Python-direct mode or feeds a parity
   golden. Zero cross-boundary deletions. The real duplication is intra-Python
   and intra-Rust.
2. **The dead code is pre-Rust debt.** Six moved-module shims with zero
   non-test importers, one never-wired streaming seam, and 27 zero-caller
   symbols whose only callers are their own tests ("dead code wearing a
   test" — invisible to the coverage gate by construction).
3. **The 183 `test_cov_wp*` files are all load-bearing.** Ten look deletable
   by line analysis and are collectively sole owners of 79 branch arcs. The
   seven coverage-redundant feature-test files carry behavioural regression
   value and are deliberately kept.
4. **The front door has seven real gaps (G1–G7)**, one of which (Set-Cookie
   destroyed on proxied redirects) makes the invite gate a hard dead-end and
   silently breaks SSO login.

## Workstream 3 — front-door and feature gaps

- **G1/G4 (redirects)**: the proxy gets its own reqwest client with redirect
  following disabled; 3xx responses pass through with their `Set-Cookie` and
  `Location` intact; absolute `Location` values naming the internal worker
  origin are rewritten to the request's gateway origin. Fixes the invite
  gate, SSO login, and the twelve legacy deep links.
- **G2/G3 (native-lane auth)**: the native `/rust/*` and `/host/*` lanes
  mirror Python's `trusted_local_owner` posture exactly. The worker's health
  payload gains the posture facts; the gateway caches them from its existing
  health polling and **fails closed** (posture unknown → native lanes refuse).
  With `LATTICEAI_REQUIRE_AUTH=true` the native lanes answer 401 with a
  machine-readable reason instead of serving the graph unauthenticated (G2)
  or dying mid-loop on a seam 401 (G3). FEATURE_STATUS states the boundary:
  the native lanes are an open-posture, single-local-owner surface in 11.5.2.
- **G5/G7 (proxied identity)**: the proxy adds `X-Forwarded-For/Proto/Host`;
  the worker computes its effective external origin from `X-Forwarded-Host`
  only when the direct peer is loopback or listed in
  `LATTICEAI_TRUSTED_PROXIES`. CSRF's `Origin == Host` fallback and the three
  absolute-URL producers (admin invite link, permission notifications, SSO
  redirect default) use it. Threat model note: browsers cannot set
  `X-Forwarded-Host`, and a local non-browser caller could already forge
  `Origin`, so this widens nothing.
- **G6 (CORS)**: the supervisor injects `LATTICEAI_CORS_ALLOWED_ORIGINS` with
  the gateway origins, mirroring the CSRF injection — the browser extension
  and any cross-origin local client work through the front door.
- **Feature gaps surfaced by the audits**: `graph_search` gains its missing
  route (`POST /api/search/graph` — it was allow-listed but unreachable);
  `multimodal_status` is wired to the route FEATURE_STATUS describes; the
  `recent_chat` context seam is investigated and either wired into the live
  assembler or the golden amended to match reality (whichever the original
  intent supports — the current state, a golden pinning behaviour the product
  never executes, is the one option that stays wrong); `tools/documents.py`
  and `core/agent_profiles.py` — live `/agent` hot-path twins with no golden —
  enter the fixture generators.
- Small honest fixes: stale `ws://` removed from both CSPs (no WebSocket
  endpoint exists); the Tauri shell no longer navigates to a dead origin when
  the gateway fails to bind.

Recorded, not fixed (with reasons): no request timeout on the proxy hop (a
blanket timeout would kill long-lived SSE; the 15-minute model endpoints rely
on the current behaviour), `request.is_disconnected()` seeing the gateway's
socket (inherent to proxying), per-IP buckets collapsing on loopback (the
gateway is loopback-only; the direct topology behaved identically).

## Release mechanics

Both waves verified on the settled tree (dev 3.14 + fresh-resolve 3.11) before
the machinery runs: bump to 11.5.2 (Cargo.lock joins the sync so the suite
stops dirtying the tree), OpenAPI regenerated (new routes), release theme
"Tight Ship", OPERATIONS title, screen-claims entry (backend-only:
all thirteen measured, none gated), release notes / CHANGELOG / README /
extension README, screenshots + GIF re-shot at 11.5.2, ARCHITECTURE System
Map labels updated (proxy semantics, posture-gated native lanes), DMG via
release:artifacts, tag + GitHub Release, main push, CI green.
