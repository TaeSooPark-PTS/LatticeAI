### 분해 프로토콜 (v10.0.1 교훈의 성문화)

**Python** — 모듈 → 동명 패키지:

1. `foo.py` → `foo/` 디렉터리. 내부를 응집 단위 서브모듈로 나눈다
   (각 ≤1,000줄, 목표 ≤700줄).
2. `foo/__init__.py`가 **모든 공개 이름 + 테스트가 참조하는 모든 이름**을
   재수출한다. 기존 `__all__` 유지. import 경로는 단 하나도 깨지지 않는다.
3. **monkeypatch 함정**: 테스트가 `patch("pkg.foo.bar")`로 패치하는
   심볼은, `bar`를 사용하는 코드와 같은 서브모듈에 두거나 테스트의 패치
   대상을 실제 위치로 갱신한다. 패키지 `__init__`에 재수출된 이름을
   패치해도 서브모듈 내부의 전역 참조는 바뀌지 않는다.
4. **모듈 전역 상태**(싱글턴, 캐시, 레지스트리)는 정확히 한 서브모듈에만
   존재한다. 순환은 의존 순서 정리로 풀고, 문자열 리터럴 지연 import로
   우회하지 않는다.
5. **AST 동등성 증명**: 분해 전(`git show HEAD:<path>`)과 후(서브모듈
   합집합)의 top-level 함수/클래스 각각에 대해 `ast.dump` 비교. import
   문과 위치 이동 외 차이 0을 확인하고 결과를 작업 노트에 남긴다.
6. `pyproject.toml`의 mypy `files` 목록을 새 경로로 갱신한다(원 모듈이
   채택돼 있던 경우 서브모듈 전부 채택).

**CSS** — `styles.css`는 이미 104개 섹션 주석으로 구조화되어 있다.
섹션 묶음별로 `frontend/src/styles/core/*.css`로 옮기고 `styles.css`
상단에서 원래 순서 그대로 `@import`한다. Tailwind v4는 unlayered 규칙이
layered 유틸을 항상 이기므로 캐스케이드는 순서 보존이 전부다.
**증명: 분해 전후 `vite build` 산출 CSS 번들이 동일해야 한다**
(해시 제외 byte-diff).

**i18n** — `brain.ts`/`workspace.ts`를 도메인별 사전 파일로 나누고 기존
파일이 병합해 `registerCopy` 한 번만 호출한다. ko/en 키 패리티 테스트와
`check_i18n_namespace_coverage.mjs`가 그대로 통과해야 한다.
`vitest.config.ts`의 커버리지 제외 패턴을 `frontend/src/i18n/**`로
넓힌다(사전은 로직이 아니다 — 기존 사유 그대로).

**검증 플로어(불변)**: Python 문·분기 100.00% (`fail_under = 100`),
프론트 4지표 100%, mypy 0 에러, ruff 클린, `npm run lint` 전 서브게이트,
전 테스트 그린. 분해는 이 플로어 위에서만 성립한다.

## 트랙 B — 기억의 연대기 (Brain Chronicle)

### 왜 이것인가

v11.1.0이 노드·엣지에 `valid_from`/`valid_to`/`superseded_by`를 심고
`edge_occurrences(observed_at)`와 `store.as_of()`/`neighbors(as_of=)`까지
구현했지만, **이 데이터를 노출하는 HTTP 엔드포인트도, 화면도 0개다.**
"두뇌가 시간을 기억한다"는 이 제품의 약속이 아직 보이지 않는다.
연대기는 그 약속을 첫 화면급 표면으로 만든다. 전부 읽기 전용이라
기존 시스템에 지장이 없다.

### 사용자에게 보이는 것

새 주 화면 **연대기** (라우트 id `chronicle`, 해시 `#/chronicle`,
everyday 내비 4번째 항목). 위에서 아래로:

1. **성장 곡선 + 스크러버** — 누적 기억(자료·개념·연결·대화)의 SVG 영역
   차트. 핸들을 잡고 끌면 아래 전체가 그 시점으로 따라온다.
2. **활동 히트맵** — 주×요일 격자, 하루의 활동 밀도. 클릭하면 그 날로.
3. **그날의 이야기** — 선택한 날짜에 두뇌에 들어온 것들을 평이한 한국어
   그룹 카드로: 자료(제목·출처), 새로 생긴 개념, 나눈 대화(첫 줄 미리보기),
   달라진 사실(superseded/모순 해소). 각 카드는 기존 화면(기억 검색,
   그래프, 대화)으로 연결된다.
4. **그때의 두뇌 (되감기)** — 스크러버가 과거에 있을 때: 그 시점의
   노드·연결 수와 그때 중요했던 개념 목록. `as_of` 읽기의 첫 노출.

빈 두뇌엔 정직한 빈 상태: "오늘부터 기록이 쌓입니다." 요약 생성이나
모델 호출은 없다 — 전부 이미 저장된 사실의 재배열이다(정직성 원칙).

### API 계약 (신규 라우터, 전부 read-only)

`latticeai/api/chronicle.py` — router-factory 규약(전체 경로, prefix 없음),
`require_user` + `gate_read`, 워크스페이스 스코프. 서비스는
`latticeai/services/chronicle.py`의 `ChronicleService`(순수 SQLite 읽기,
날짜 버킷은 `latticeai/core/timezones.py` 기준).

```
GET /api/chronicle/overview
  → { first_activity_at, last_activity_at,
      totals: { sources, entities, connections, conversations },
      series: [ { date, sources, entities, connections, conversations } ] }

GET /api/chronicle/day/{date}          # YYYY-MM-DD, LATTICE_TZ 기준
  → { date, counts, groups: {
        sources:       [ { id, title, source_type, captured_at, node_id } ],
        entities:      [ { id, label, type, created_at } ],
        conversations: [ { conversation_id, preview, messages, started_at } ],
        changes:       [ { kind, label, at, node_id } ] } }

GET /api/chronicle/as-of?ts=<ISO8601>
  → { ts, stats: { entities, connections },
      top_entities: [ { id, label, type, importance_score } ] }
```

데이터 원천: `ingestion_provenance(created_at, captured_at)`,
`nodes_v2`/`edges_v2`(`created_at`, temporal 3열),
`conversation_messages(timestamp)`, `edge_occurrences(observed_at)`.
`as-of`는 `store.as_of()` 계열을 통해서만 읽는다(중복 구현 금지).
등록은 `build_phases.py` platform_features 단계에 직접 include.
스키마 변경 0, 쓰기 0.
