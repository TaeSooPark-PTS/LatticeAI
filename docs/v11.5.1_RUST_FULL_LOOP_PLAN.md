## Y1 — Three AI-Worker Seams (Python, Additive)

Recon confirmed: there is no bare LLM completion endpoint, no HTTP proposal-creation endpoint, and `/tools/*` enforces direct-surface `enforce_policy`, making it unsuitable for agent-loop dispatch.

- `POST /agent/llm` — thin wrapper around `LLMRouter.generate_as`: `{model_id?, message, context?, max_tokens?, temperature?}` → `{text}`. Zero history/persistence side effects. Protected by `require_user` + rate limit.
- `POST /agent/tool` — loop-dedicated governance seam: `{tool, args, user_email?, workspace_id?}` → `check_role` + `dispatch_tool(HOOKS, source="agent")` returning `{result}|{error}`. **Server-side mode-invariant guards remain active** (unbypassable): `is_circuit_breaker` / destructive policy → `403`, `classify_tool_call.fail_closed` → `409`. Gated behind `LATTICEAI_AGENT_TOOL_SEAM=1` (off by default — injected only by the host into its managed worker), otherwise `404`. Mode gating itself is owned by the Rust kernel (preflight).
- `POST /agent/change-proposal` — exposes `ChangeProposalService.review(...)` verbatim (proposal-first path) behind the same seam gate.

All three maintain 100% statement/branch coverage, Korean/English localization, and regenerated OpenAPI specs.

## Y2 — `lattice-agent`: Loop Orchestrator (1:1 with Recon §1 Spec)

- Deterministic helper ports + goldens: `extract_action_details` (6-stage tolerance chain), `normalize_plan` (7 rules in order), `infer_project_manifest` / `infer_file_target`, `artifact_checklist`, `requirement_coverage`, `_truncate_strings`, `filter_learnings`, `PhaseBudgets` / `TranscriptBudget` defaults, verification mapping table (`UNAVAILABLE` / `PASS`-no-evidence / `PASS`-unmet / `ROLLBACK` / retry / contradictory verdict), and execution-loop rules (budget, `parse_failure_budget`/escalate, `final`, `_is_repeated_create`, `SCOPED` forced injection, `step_index` formula).
- State machine: `run_to_completion` transition table + 200-step cap (measured on `state_history` length), 3-tier rollback (`git → snapshot → none`, always terminating in `FAILED`) — snapshot/restore runs natively in Rust (reusing sandbox `Workspace`).
- Approval store: `run_id`/token generation (`urlsafe` 16/32), SHA-256 token hashing, 600s TTL, 86,400s post-expiry retention → `410` + replan, atomic JSON persistence, preserving the exact `serialize/restore_run_context` contract (unknown state → `WAITING_APPROVAL`).
- Worker client: `/agent/llm` (plan/execute/verify/memory), `/agent/tool` (non-native tools), `/agent/change-proposal` (strict proposals), while native execution runs the X4 kernel's read-only set.
- Routes: `POST /rust/agent/run` (SSE `agent_step` events + final payload isomorphic to Python `/agent`), `POST /rust/agent/resume`, `GET /rust/agent/approvals`. `lattice-host` injects `LATTICEAI_AGENT_TOOL_SEAM=1` into `worker_env` and updates `mounts` signatures.
- Goldens: Python generator commits a deterministic helper grid + scripted fake-LLM end-to-end state trajectories (`plan → ... → terminal`, across 3 modes × scenarios: clean `DONE`, parse-budget exhaustion, repeated-create guard, approval pause/resume, expiry `410`, verify retry → `FAILED`/`ROLLBACK`) as bidirectional contract JSON. Scripted LLM calls keep both Rust and Python deterministic against the same transcripts.

## Y3 — Native Document-Generation Context (B) (`lattice-retrieval`)

1:1 with recon §4 spec: `search_for_document_generation` (2-lane `LIKE` candidates, `0.5/0.3/0.2` weights + `1.2` type boost, `log1p(edge)/4`, 14-day half-life, reproducing insertion-order tiebreaks), `multi_hop_context` (hop label semantics by expansion round; hop-2 only via edge endpoints), and the full `retrieve_context_for_generation` contract (self-model block budget accounting including join newlines, 4 fixed sections, `relevance: {:.2f}` Markdown, `\n### ` backoff trimming, sources dedup chain, trace). `summary_for_prompt` is ported as a store read. Gateway route: `POST /rust/context/document`. Goldens add docgen-typed nodes to the fixture store (re-verifying existing goldens) with new Rust and contract pytest suites.
