# Lattice AI 10.2.0 — Load-Bearing Fixes

> **Status: historical** — point-in-time release note.

릴리스일: 2026-07-29

## 한 줄 요약

10.1.1 전체 코드 리뷰(71/100)에서 나온 **12개 항목을 전부 처리**했습니다.
공통점은 하나입니다 — **맞게 쓰였지만 제 역할을 할 수 없던 코드**.

## 1. 가려져 있던 커넥션 누수

```python
with sqlite3.connect(...) as conn:   # 커밋은 한다. 닫지는 않는다.
```

70곳 이상이 이 관용구에 기대고 있었습니다. CPython 참조카운팅이 곧바로
회수해서 평소엔 보이지 않았습니다. **프레임을 붙잡는 무언가**가 생기는 순간
드러납니다 — 프로파일러, 로그에 남은 traceback, 커버리지 트레이서.

```
before:  50회 연결 후 열린 fd 111개, __exit__ 이후에도 커넥션 사용 가능
after:   0개, ProgrammingError (정상적으로 닫힘)
```

`StorageEngine.session()`을 추가하고 store 헬퍼들을 닫는 컨텍스트 매니저로
바꿨습니다. 호출부 70여 곳은 **한 줄도 안 바뀌었습니다.**

## 2. 그래서 커버리지를 처음으로 측정했습니다 — 71%

측정할 수 없었던 이유가 바로 위 누수였습니다. 트레이서가 프레임을 잡아
fd를 고갈시켜, `pytest --cov`가 **400개쯤 실패**했습니다. 즉 이 저장소는
자기 커버리지를 **한 번도 알지 못한 채** 10.1.1까지 왔습니다.

```
TOTAL   32935 stmts   9646 missed   71%
```

CI에 **70% 하한**을 넣었습니다. 목표가 아니라 바닥입니다.

## 3. 발화할 수 없던 프라이버시 가드

```python
HARD_BLOCK_NODE_TYPES: Set[str] = frozenset({
    # Keep empty for v1 scaffolding
})
```

타입 목록은 **비어 있었고**, 메타데이터 플래그(`sensitive`/`private`/
`do_not_share`/`local_only`)를 **세팅하는 코드가 제품 전체에 없었습니다.**
필터는 정확했고 배선도 정확했지만, 참이 될 수 없는 조건문이었습니다.

세 방향으로 채웠습니다:

| 경로 | 무엇 |
| --- | --- |
| 타입 | `Credential` `Secret` `ApiKey` `Token` `Password` `PrivateKey` |
| 자동 | 수집 시 `.ssh/` `.aws/` `.gnupg/` `.env` `id_rsa` `.pem` … 자동 플래그 |
| 수동 | 미리 보기 목록에서 기억별 **"내보내지 않기"** |

자동 규칙은 **일부러 좁게** 잡았습니다. 경로는 증명할 수 있지만 내용 추측은
양쪽으로 틀립니다 — `credentials-policy-draft.md`를 격리하지 않고,
`README.md`도 건드리지 않습니다.

수동 토글은 **미리 보기 목록 위**에 뒀습니다. 사용자가 "무엇이 나가는지"를
보고 있는 그 순간이, 개별 기억을 판단할 수 있는 유일한 시점입니다.

## 4. 나가는 것에 리댁션과 감사 기록

`redact_secret_text()`는 로그·감사·API 프리뷰에 이미 걸려 있었고,
**실제로 바이트가 나가는 단 하나의 경로에만** 빠져 있었습니다. 이제 걸립니다.

그리고 모든 전송이 **provider 호출 전에** 감사 기록을 남깁니다:

```
cloud_egress  outcome=sent  mode=cloud_allowed  provider=...
              node_ids=[...] node_count=3 token_estimate=412
```

**내용이 아니라 형태만** 기록합니다 — 나간 지식을 증명하려고 디스크에 한 번
더 쓰는 건 그 자체로 유출입니다. 거절도 기록합니다("아무것도 안 나갔고,
이유는 이것").

## 5. 침묵을 관측 가능하게

`except Exception: pass` **112곳**. 동작으로는 대부분 옳습니다 — 선택적
하드웨어 probe 실패로 서버가 죽으면 안 되니까요. 옳지 않은 건 **아무 흔적도
남지 않는다**는 점입니다. 그 경로의 진짜 버그와 "그 기능이 그냥 없음"이
구분되지 않습니다.

```python
except Exception:
    quiet()      # 동작 동일. DEBUG로 파일·함수·줄번호와 함께 기록.
```

`except: pass`는 이제 **lint 에러**입니다.

## 6. 그 밖의 리뷰 항목

- **클라우드 턴이 검색을 2번** 돌리고 첫 결과를 quality dict만 빼고 버렸습니다 → 1번
- **벡터 유사도가 차원 불일치 시 조용히 잘라내** 그럴듯한 무의미 점수를 냈습니다
  → 양쪽 차원을 명시하고 예외. 에러가 조용한 오답보다 낫습니다
- **`tempfile.mktemp()` TOCTOU 레이스** 2곳 → `mkstemp`
- **루프 변수를 참조로 캡처하는 클로저** 3곳 → 기본인자 바인딩
- **ruff** pyflakes → `B,S,I,SIM,RET,C901` 추가. 남은 건 전부 수정하거나 **이유를 적었습니다**
- **mypy** 신뢰 핵심 13개 모듈에 도입 (`npm run typecheck:python`)
- **CI에 macOS + Python 3.14** — `.dmg`를 내는 플랫폼과 매일 개발하는 버전이
  둘 다 테스트된 적이 없었습니다
- **`workspace_os.py`** 1354 → 1130줄

## 하지 않은 것과 그 이유

`app_factory._build`는 **여전히 1,343줄 한 함수**입니다.

이 함수의 각 구역은 **약 34개의 지역 변수를 공유**합니다. 쪼개려면 그것들을
파라미터로 넘기거나 런타임 컨텍스트 객체를 도입해야 하는데, 그건 기계적
추출이 아니라 **아키텍처 변경**입니다. 12개 항목과 함께 밀어 넣기보다
별도 릴리스에서 다루는 게 맞다고 판단했습니다.

10.0.1의 `agent.py` 분해가 안전했던 건 그 안에 **순수 함수 440줄**이 있었기
때문입니다. 이 함수는 형태가 다릅니다.

C901 예외 목록에 이름을 적어, **미룬 결정이 보이도록** 했습니다.
