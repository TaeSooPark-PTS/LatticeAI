# Lattice AI 10.6.0 — Promoted Panels

> **Status: historical** — point-in-time release note.

릴리스일: 2026-08-03

## 한 줄 요약

**10.5.0이 각 화면의 말을 바꿨다면, 10.6.0은 각 화면의 자리를 바꿉니다.** 주요
화면들은 그동안 '동등한 탭 한 줄'로 열렸습니다. 그건 처음 온 사람에게 선택지가
무엇인지 알기도 전에 고르라고 요구하는 배치입니다. 이제 모든 화면은 **여기까지
오게 만든 질문에 답하는 패널 하나**로 열리고, 나머지는 그 아래로 내려갑니다.
기능은 하나도 지우지 않았습니다 — 모든 패널은 여전히 같은 페이지에 있고, 다만
화면 맨 위를 두고 경쟁하지 않습니다.

라벨만 바꾸고 배치를 그대로 두는 것은 이번 과제의 실패 조건이었습니다. 아래는
실제로 옮기고, 묶고, 덜어낸 것들입니다.

---

## 1. 화면마다 1순위 패널 하나

### 자료 (Capture) — 탭 네 개 → 카드 한 개

파일 올리기 · 폴더 연결하기 · 웹페이지 저장하기 · 진행 상황이 **페이지 수준 탭
네 개**로 나란히 있었습니다. 넷 다 같은 무게라, 무엇부터 해야 하는지 화면이
말해주지 않았습니다.

이제 페이지는 **`자료 추가하기` 카드 하나**로 열립니다.

> 자료 추가하기
> 파일, 폴더, 웹페이지 중 무엇을 넣을지 고른 다음 바로 추가하세요.

세 가지 방법은 그 카드 **안의 선택지**가 되었고(탭이 아니라 `role="group"`의
버튼 묶음), 고른 방법의 입력 폼이 같은 카드 안에서 바로 열립니다. 진행 상황과
연결된 폴더·업로드된 문서는 아래 조용한 2열 영역(`.capture-secondary`)으로
내려갔습니다 — 사라진 게 아니라, **항상 보이되 1순위는 아닌** 자리로 옮긴
것입니다. 진행 상황은 오히려 탭 뒤에 숨어 있던 이전보다 더 잘 보입니다.

`#/my-computer`, `#/capture-browser`, `#/pipeline` 딥링크는 그대로 동작합니다.

### 작업 (Work) — 빈 입력창 대신 '나를 기다리는 것'

작업 화면은 **새로 맡길 일**(빈 목표 작성기)로 열렸습니다. 처음 온 사람에게
빈 입력창을 내미는 화면입니다. 이제 **검토함**으로 열립니다 — 지금 내 결정을
기다리는 자동화 제안 목록입니다.

- 탭 순서: `지금 하는 일과 검토할 일` → 목표 → 레시피 → 보호 장치 → 도구 권한
- 그 안에서도 `검토함`이 `실행`보다 앞
- 셸의 '작업' 링크 목적지가 `#/agents` → `#/review`로 바뀌었습니다

제목과 설명도 탭을 따라갑니다. 이전에는 어느 탭에 있든 같은 문장이 붙어 있어서
제목이 지금 보고 있는 것을 설명하지 못했습니다.

### AI 모델 (Library) — 탭보다 먼저 답하기

"지금 무슨 모델이 돌고 있나, 바꿀 수 있나"는 이 화면에 오는 이유 그 자체인데,
그 답은 탭 안쪽 통계 칸에 있었습니다. 이제 탭 **위에** 카드로 있습니다.

> 지금 작동 중인 모델 · Qwen3-VL 8B `사용 중`
> 다른 모델로 바꾸기 — 이미 받아둔 모델이라 한 번만 누르면 바뀝니다. 저장된
> 기억은 그대로예요.

바꾸기 목록에는 **이미 내려받았고 이 기기에서 실행 가능한** 모델만 올라옵니다.
아직 준비되지 않은 모델을 한 번 눌러 바꿀 수 있는 것처럼 보여주지 않습니다.
켜진 모델이 없으면 카드는 그 사실을 말합니다("아직 사용할 모델이 없어요").

### 대화 (Brain 홈) — 블록 다섯 개 → 카드 하나

인사말, 입력창, 자료 추가 줄, 자율성 다이얼, 추천 질문이 각각 따로 떠 있는
블록이었습니다. 이제 **테두리 있는 스테이션 하나** 안에 전부 들어갑니다. 자료
추가와 자율성은 서로 경쟁하던 두 줄에서 **한 줄(`.brain-station-toolbar`)**로
합쳐졌습니다. 카드 안 어디든 입력을 시작하면 카드 전체가 떠오릅니다
(`:focus-within`).

Brain 그림은 7rem → 5.4rem으로 줄였습니다. 화면의 주인공이 아니라 **입력창을
소개하는 역할**이기 때문입니다.

### 기억 (Memory) — 연결 지도는 세 번째 탭이 아니라 하위 화면

동등한 탭 세 개 중 하나였던 연결 지도는, 이제 기억 화면에서 **버튼 하나 뒤**로
갑니다.

> 연결 지도 열기 — 기억들이 서로 어떻게 이어져 있는지 그림으로 봅니다.

지도에 들어가면 탭 줄 대신 `← 기억 화면으로 돌아가기`가 나옵니다. 돌아가는 길이
화면에 적혀 있는 하위 화면이지, 나란한 목적지가 아닙니다. `#/knowledge-graph`
딥링크는 그대로입니다.

### 설정 (System) — 탭 일곱 개 → 이름 붙은 묶음 셋

평평한 일곱 개 탭을 성격대로 묶고 각 묶음에 이름을 붙였습니다.

| 묶음 | 들어 있는 것 |
| --- | --- |
| 나와 작업공간 | 계정, 작업공간 |
| 내 데이터 보관 | 스냅샷, 활동 |
| 동작 방식과 연결 | 설정, 네트워크, 관리 |

## 2. 매일 쓰는 곳과 관리하는 곳을 갈랐습니다

여섯 개 목적지가 한 줄에 동등하게 있었습니다. 매일 쓰는 것과 가끔 손보는 것이
같은 무게였습니다.

- **주 내비게이션**: 대화 · 자료 · 기억
- **관리**: 작업 · AI 모델 · 설정

관리 목적지는 넓은 화면에서 상단바 오른쪽 링크로 나오고, 좁은 화면에서는
'더보기' 메뉴 안으로 접힙니다. 중요한 건 **두 벌이 아니라 배열 하나에서
렌더링된다**는 점입니다 — 복사본 두 개는 반드시 어긋나기 때문입니다. 어느 쪽을
보여줄지는 `shell.css`의 **단일 브레이크포인트(960px)**가 정합니다. 그래서 둘 다
보이거나 둘 다 사라지는 상태가 만들어지지 않습니다.

메뉴 안 목록도 이제 '화면 이동'이 아니라 **관리**라고 부릅니다. 이전에는 주
내비게이션과 메뉴 안 목록이 **둘 다 "화면 이동"**이었습니다. 스크린리더의 랜드마크
목록에는 구분할 수 없는 내비게이션 두 개가 떴습니다. 이제 관리 쪽은 상단바
쌍둥이와 이름(`관리 화면 이동`)을 공유하고, 그 둘은 동시에 보이지 않습니다.

## 3. 이름이 가리키는 화면으로 실제로 가게 됐습니다

레이아웃을 다시 짜다 나온, 원래부터 깨져 있던 결함들입니다.

**`#/act/review`는 한 번도 검토함을 연 적이 없습니다.** 명령 팔레트와 오늘의
브리핑은 늘 `<화면>/<탭>` 형태를 내보냈는데, 그 형태를 해석하는 코드가
없었습니다. 그래서 `#/act/review`, `#/act/workflows`, `#/brain/graph`는 전부
조용히 Brain 홈으로 떨어졌습니다. `parseHash`가 이 형태를 마지막 단계로
해석합니다 — 마지막인 이유는 명시적 별칭이 항상 이겨야 하기 때문입니다.

**명령 팔레트는 목적지 목록의 사본을 따로 들고 있었습니다.** `routes.ts`의
`commandRoutes`는 팔레트가 읽지 않는 두 번째 목록이었습니다. 그래서 셸의 '작업'을
`#/review`로 옮겨도 팔레트의 '작업'은 옛 목적지로 갔습니다 — **같은 이름이 어떻게
도달했느냐에 따라 다른 화면**을 뜻했습니다. 이제 목록은 하나이고, 팔레트가 그것을
읽습니다.

**포커스 트랩이 보이지 않는 링크를 세고 있었습니다.** 메뉴는 관리 링크의 사본을
들고 있고 CSS가 그중 하나를 숨깁니다. 숨은 링크도 DOM에는 남아 있어서, 단순한
`querySelectorAll`은 브라우저가 포커스를 주지 않을 요소를 경계로 삼았습니다.
메뉴를 열었을 때 초기 포커스가 `display:none` 요소로 가서 **아무 일도 일어나지
않는** 경우도 있었습니다. 이제 실제로 렌더링된 요소만 셉니다.

## 4. 이 배치를 지키는 테스트

`tests/visual/v3.spec.js`에 추가된 것들:

- **관리 링크는 정확히 한 곳에만** — 390px부터 1440px까지 열 개 너비를 훑으며,
  상단바 사본과 메뉴 사본이 동시에 보이거나 동시에 사라지면 실패합니다. 상단바
  넘침과 메뉴 버튼 잘림도 함께 봅니다.
- **모든 내비게이션 랜드마크에 이름이 있고, 이름이 겹치지 않는다** — 세 가지 너비
  에서 검사합니다.
- **Brain 홈은 테두리 카드 하나** — 입력창·자료 추가·자율성이 모두 그 안에 있고,
  툴바가 둘을 한 줄로 묶고 있는지 확인합니다.
- **연결 지도는 하위 화면** — 탭이 둘뿐이고, 지도는 버튼으로 열리며, 돌아가는
  버튼이 있고, 지도에서는 탭 줄이 없습니다.
- **자료 화면은 스테이션 하나로 시작** — 페이지 수준 탭이 없고, 방법 버튼 세 개가
  한 카드 안에 있으며, 딥링크 세 개가 여전히 동작합니다.
- **AI 모델 화면은 작동 중인 모델을 먼저 답한다** — 카드가 탭 줄보다 앞에 있고,
  레지스트리 좌표가 아니라 사람이 읽는 이름을 보여줍니다.
- **셸 링크와 명령 팔레트가 같은 화면을 연다** — '작업'은 양쪽 모두 `#/review`.

`tests/visual/mock_server.cjs`는 새 화면이 실제로 그려지도록 두 엔드포인트를
추가로 서빙합니다: `POST /models/load`(한 번 눌러 모델 바꾸기)와
`GET /knowledge-graph/local/health`(자료 화면 2열의 폴더 상태 카드). 이 라우트가
없으면 릴리스 스크린샷은 반쪽짜리 화면으로 찍힙니다.

## 5. 릴리스 증거

`output/release/v10.6.0/` 스크린샷 12장과 워크스루 GIF를 새 레이아웃으로 다시
찍었습니다. 캡처는 앱의 실제 기본값인 `basic` 모드, 한국어로 진행됩니다.

이번에 캡처 스크립트도 한 곳 고쳤습니다. 진행 상황이 자체 탭에서 자료 화면
2열로 옮겨졌기 때문에 `#/pipeline`과 `#/capture`가 같은 페이지를 그리고,
`11-knowledge-journey.png`가 `06-capture.png`와 **바이트 단위로 동일**하게
찍혔습니다. README는 이 둘을 서로 다른 항목으로 싣습니다. 이제 11번 프레임은 세
단계 카드 자체를 찍습니다.

## 호환성

- 백엔드 동작 변경 없음. `frontend/openapi.json`은 10.5.0 대비 `info.version`만
  다릅니다.
- 기존 딥링크는 모두 유지됩니다. 셸의 '작업' 진입점만 `#/agents` → `#/review`로
  바뀌었고, `#/agents`는 그대로 목표 작성기를 엽니다.
- 삭제된 기능 없음. 옮겨진 기능만 있습니다.
