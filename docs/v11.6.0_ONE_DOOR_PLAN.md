# v11.6.0 — One Door (Design Document)

> Status: planned → implemented. One-sentence goal: **after this release,
> Python is used strictly as the AI Worker.** Move the ~450 platform routes
> left outside the worker boundary in v11.5.1 into Rust, leaving the Python
> worker with only the worker-owned compute defined in v11.5.1 — LLM inference,
> tool/render compute, proposal staging, document parser matrix, and embedding
> production.

## Verified Recon Baseline (2026-08-14)

- 464 Python routes = `KEEP_WORKER` **25** + `PORT_STATE` **313** + `PORT_ORCH` **108** + `STATIC` **18**. Clients actively hit ~190 routes (all contracts documented).
- Rust natively served 24 routes (~5%). The proxy was solid (streaming, cookies, multipart, SSE intact), but the gateway had no native authentication.
- Missing infrastructure: auth/sessions, SQLite write side, server message i18n (292 Korean literals), native CSRF/CORS, SSE piping, multipart, rate limiting, OpenAPI composition, SPA serving, and workspace scoping.

## Target Python Worker Surface (25 Routes — Everything Else Moves)

`/health` · `/agent/{llm,tool,change-proposal}` · `/api/index/{drain,rebuild}` · `/api/embeddings/{status,providers}` · `/models` `/models/{load,switch/*,unload/*,unload-all}` · `/engines/prepare-model{,/stream}` · `/tools/{read_document,pdf_pages,create_docx,create_xlsx,create_pptx,create_pdf}` · `/upload/document` · `/api/ingestion/multimodal` · `/api/capture/voice{,/status}` · (plus `/knowledge-graph/ingest` initially retained as the single-writer graph seam)

Plus three v11.6.0 transitional additive seams (§WP-I6): history recording (`redact → audit → store → ingest` chain), graph write delegation, and GPU sysinfo — all callable only from the loopback gateway host.

## Design Decisions

1. **Topology** — `lattice-host` becomes the product server, serving 439 of 464 routes natively via `axum` handlers **at their exact existing paths** (zero client changes). Proxy fallthrough is inverted into an allowlist forwarding only the 25 worker seams — the remaining proxy table *is* the worker contract.
2. **Storage Write Ownership (Elevated 2026-08-14)** — Confirmed principle: **Rust owns the entire write path.** Not only platform state (users/sessions, workspaces, review queue, proposals, settings, jobs, history), **the Knowledge Graph write engine also moves to Rust** (Wave 2.5 §W1: native store write/ingest/projection/provenance/vector writes with row-level parity goldens against the Python store). The Python worker becomes a **stateless pure-compute worker**: `/worker/embed` returns vectors and Rust stores them; document render seams return bytes and Rust writes files. During transition, Wave 2 calls state seams (`/worker/graph/mutate`, `/worker/chat/record-turn`), and Wave 2.5 (§W3) swaps those callers onto the native write engine and deletes the state seams. All three file writers identified during scout (`write_file`/`edit_file`, proposal approve) unify under `lattice-agent` sandbox `Workspace` (including native proposal apply).
3. **Authentication** — New `lattice-auth` crate: sessions, users, login, roles, workspace scoping, rate limiting, and the 7-branch CSRF Origin port. Locks Python's hand-rolled cookie parser semantics and **exact rejection bodies** in fixtures. Because Python checks auth inside handler bodies rather than OpenAPI declarations, auth requirements are transcribed directly from handler source into each WP spec.
4. **OpenAPI Contract Pipeline** — `frontend/openapi.json` stays the single contract source of truth. Specs for Rust-migrated routes live alongside their crates as JSON fragments, and Rust tests assert `mounted_routes == spec_paths`. `scripts/export_openapi.py` becomes a composer merging the trimmed worker-only app spec with Rust fragments while keeping the drift gate active.
5. **i18n** — `lattice-core::messages` Korean/English catalog. As routes migrate, their localized literals move alongside them, and `check_server_i18n.mjs`'s router list shrinks accordingly.
6. **SSE** — `POST /chat` (orchestration: `redact → audit → worker LLM stream → store → ingest`), `/engines/prepare-model/stream` (kept proxied to worker), and `/agent` (reusing the v11.5.1 native loop directly on the gateway path). **No `Accept` header negotiation** — VS Code sends only body `stream: true`.
7. **Static / SPA** — Gateway `ServeDir` for `/app`, `/static`, `/icons`, `manifest.json`, `favicon.ico`, `sw.js`, plus `GET /chat` redirect.
8. **Crate Layout** — Three new crates: `lattice-auth`, `lattice-platform` (workspace, admin, features, permissions, review, proposals, mcp, marketplace, plugins, hooks, registry), and `lattice-chat` (chat orchestration + hybrid cloud lane). Domain-aligned routes extend existing crates (`retrieval`: memory/brain reads; `ingest`: `local_files`/capture; `jobs`: index). Update `RUST_CRATES` in bump/version consistency checks.
9. **Python Slimming** — **Deletion** over a `LATTICEAI_WORKER_ONLY=1` flag: remove `latticeai`/`lattice_brain` modules outside the keep-set along with their tests, maintaining 100% coverage over the reduced denominator per arc. Synchronize all 10 gate files (`mypy` paths, `setuptools` packages, wheel smoke modules, `MANIFEST`, `package.json` files, `product_readiness` needles, `FEATURE_STATUS` `_NOT_HTTP_PATHS`, server app decomposition test, release-history test, i18n router list).
10. **Clients / Entrypoints** — SPA, extensions, and Telegram remain unchanged (paths preserved). `bin/ltcai.js`, `cli/entrypoint.py`, and `src-tauri` `direct/external` topologies rewire to require the `lattice-host` front door. Worker entrypoint (`server:app`) stays as spawned by the host.

## Verification Protocol (Across All WPs)

- **Capture-replay parity**: before deleting Python handlers, generate golden request/response fixtures via `TestClient` (success + auth rejection + error branches) into `rust/fixtures/http/<family>.json` and replay them in Rust tests — full branch coverage for the ~190 client-touched routes, representative branches for the rest.
- **Native proof**: assert **0 worker calls** against `lattice-host`'s `FakeWorker` (following `gateway_mounts.rs`).
- Shared files (`rust/Cargo.toml`, `gateway/{mod,mounts}.rs`, `app_factory.py`, `pyproject.toml`) are edited **only by the integrator**. Each WP owns its crate/module files and leaves wiring notes.

## Work Packages

Wave 1 — Infrastructure (parallel):
- **I1** `lattice-core::db` write side (WAL, `busy_timeout`, pool) + table ownership map + config structs
- **I2** `lattice-auth` + gateway auth/CSRF/security-header layers
- **I3** `lattice-core::messages` ko/en catalog + extraction
- **I4** Gateway static/SPA serving + `ui_redirects` + `static_routes`
- **I5** OpenAPI composer pipeline
- **I6** Three additive Python worker seams + worker-only app profile

Wave 2 — Route Families (parallel, fixtures generated first):
- **R1** `workspace` (56) + `scope` + `invitations` + `permissions` → `platform`
- **R2** `admin` + `security_dashboard` + `features` + `funnel` + `setup` → `platform`
- **R3** auth routes (`login`/`register`/`account`) → `auth` (merged into I2)
- **R4** full `chat` family + hybrid lane → `lattice-chat` (highest complexity)
- **R5** `memory` + `brain_intelligence` + `garden` + `chronicle` + `command_center` + `evidence_actions` → `retrieval`/`platform`
- **R6** `knowledge_graph` + `search` + `index` + `local_files` + `local_knowledge` + `browser` → `ingest`/`retrieval`
- **R7** `review_queue` + `change_proposals` + `automation_intelligence` + `hooks` → `platform`
- **R8** `mcp` + `marketplace` + `plugins` + `agent_registry` + `agents` + non-document `tools` → `platform`/`agent`
- **R9** `portability` + `network` + `network_boundary` + `realtime` + `project_sessions` + voice listing + `computer_use` surface → `platform`
- **R10** non-MLX models catalog/recommendations + `permission_mode` + `workflow_designer` + remainder → `platform`

Wave 2.5 — Write-Path Sovereignty Transfer (Rust = Write Owner, Python = Pure Compute):
- **W1** Native KG write engine: mirror port of `lattice_brain` graph write/ingest/projection/provenance/vector writes + row-level parity goldens. `/knowledge-graph/ingest`, `/upload/document`, and index drain/rebuild become native.
- **W2** Pure-compute Python seams: `/worker/embed` (returns vectors), `/worker/render/{docx,xlsx,pptx,pdf}` (returns bytes), aligned parsing/ASR/multimodal seams; prepare retirement of the 3 state seams.
- **W3** Wave-2 caller cutover: replace `WorkerSeamClient` state-seam calls with native write engine / audit sink; native port of redaction rules; entire `record-turn` chain (`redact → audit → store → ingest`) in Rust.
- **W4** Native mutating tool handlers: shrink `/agent/tool` to a compute-only allowlist while write tools route through sandbox / graph-write.

Wave 3 — Slimming & Rewiring:
- **P1** Python deletion (per keep-set) + test cleanup + synchronization of all 10 gate files
- **P2** Rewire `bin/ltcai.js`, `entrypoint`, and Tauri topology
- **P3** Retire dead golden generators (migrate reference implementations or deprecate explicitly)

Wave 4 — Release: bump 11.6.0 (31 targets) → regenerate OpenAPI → `releaseTheme` "One Door" → docs sync (`README` current release, media paths, Release History pruning pre-11.0.0 + assertion test update, `RELEASE_NOTES`, `CHANGELOG`, `ARCHITECTURE` System Map rewrite, `SECURITY` 11.6.x, `FEATURE_STATUS`, `release_screen_claims` 11.6.0 entry) → `build:assets` → `release:evidence` (13 shots + GIF) → 4-way local verification (fresh venv, non-editable install, Linux container, Rust container) → artifacts → commit & push `main` → green CI.

## What Remains After Completion

Python AI Worker: inference, compute tool execution, proposal staging, document parsers, embeddings, and compute seams (25 HTTP routes + seams). Everything else runs natively in Rust. That is "One Door": `lattice-host` is the single door every user and client knocks on.
