# v11.6.0 — One Door (설계 문서)

> 상태: 계획 → 구현. 목표는 한 문장이다: **이 릴리스가 끝나면 Python은
> AI Worker로만 쓰인다.** v11.5.1이 "설계상 최종 형태"로 남겨 둔
> 플랫폼 라우트 박스(~450 라우트)를 Rust로 옮기고, Python 워커는
> v11.5.1이 정의한 워커 소유물 — LLM 추론, 도구 핸들러 실행과
> 그래프·파일 쓰기(단일 작성자), 제안 스테이징, 문서 파서 매트릭스,
> 임베딩 생산 — 만 남긴다.

## 정찰 확정 수치 (2026-08-14)

- Python 라우트 464개 = KEEP_WORKER **25** + PORT_STATE **313** +
  PORT_ORCH **108** + STATIC **18**. 클라이언트가 실제 밟는 경로는
  ~190개(전 계약 문서화됨).
- Rust 네이티브는 24 라우트(~5%). 프록시는 견고(스트리밍·쿠키·
  멀티파트·SSE 무손상)하나 게이트웨이 자체 인증은 없다.
- 결핍 인프라: 인증/세션, 쓰기측 SQLite, 서버 메시지 i18n(한글
  리터럴 292), CSRF/CORS 네이티브, SSE 파이프, 멀티파트, 레이트리밋,
  OpenAPI 생성, SPA 서빙, 워크스페이스 스코핑.

## 설계 결정

1. **토폴로지** — lattice-host 게이트웨이가 제품 서버가 된다. 464개
   중 439개 라우트를 **기존 경로 그대로** 네이티브 axum 핸들러로
   서빙한다(클라이언트 무변경). 프록시 폴스루는 워커 시임 25개만
   통과시키는 allowlist로 뒤집는다 — 남는 프록시가 곧 워커 계약이다.
2. **저장소 쓰기 분할 (2026-08-14 상향)** — 사용자 기준 확정: **Rust가
   쓰기 경로 전체의 주인이다.** 플랫폼 상태(사용자/세션, 워크스페이스,
   리뷰 큐, 제안, 설정, 잡, 히스토리)뿐 아니라 **지식 그래프 쓰기
   엔진도 Rust로 이관한다**(Wave 2.5 §W1: store write/ingest/projection/
   provenance/벡터 쓰기 네이티브 — Python 스토어와 행 단위 패리티 골든).
   Python 워커는 상태를 소유하지 않는 **순수 계산 워커**가 된다:
   임베딩은 `/worker/embed`가 벡터를 반환하고 Rust가 저장하며, 문서
   생성은 렌더 시임이 바이트를 반환하고 Rust가 파일을 놓는다. 전환
   순서상 Wave 2는 상태-시임(`/worker/graph/mutate`,
   `/worker/chat/record-turn`)에 대고 작업하고, Wave 2.5(§W3)가 그
   호출부를 네이티브 쓰기 엔진으로 교체한 뒤 해당 시임을 폐지한다.
   Scout가 찾은 "작성자 3곳"(write_file/edit_file, proposal approve)은
   lattice-agent sandbox Workspace로 일원화한다(제안 apply 포함 —
   네이티브).
3. **인증** — 신규 `lattice-auth` 크레이트: 세션/사용자/로그인/역할/
   워크스페이스 스코프/레이트리밋 + CSRF Origin 7분기 포트. Python의
   수제 쿠키 파서 의미론과 **정확한 거부 본문**까지 픽스처로 결속한다.
   인증은 Python에서 핸들러 본문 안에 있으므로 OpenAPI가 아니라
   본문 전사로 옮긴다(라우트 WP 명세에 인증 요구를 명기).
4. **OpenAPI 계약 파이프라인** — `frontend/openapi.json`이 계약의
   단일 출처로 유지된다. Rust로 간 라우트의 스펙은 크레이트 옆에
   데이터(JSON 프래그먼트)로 살고, Rust 테스트가 "마운트된 라우트 ==
   스펙 경로"를 단언한다. `scripts/export_openapi.py`는 워커-전용
   앱(축소된 app_factory) 스펙 + Rust 프래그먼트를 합성하는 컴포저로
   재작성한다. 드리프트 게이트는 그대로 문다.
5. **i18n** — `lattice-core::messages` ko/en 카탈로그. 라우트가
   이주할 때 해당 한글 리터럴도 함께 이주한다.
   `check_server_i18n.mjs`의 라우터 목록은 축소분만큼 갱신.
6. **SSE** — `POST /chat`(오케스트레이션: redact→audit→워커 LLM
   스트림→store→ingest 시임), `/engines/prepare-model/stream`
   (워커 프록시 유지 — KEEP), `/agent`(v11.5.1 네이티브 루프 재사용,
   경로만 게이트웨이가 직접 답함). **Accept 헤더 협상 금지** —
   VS Code는 body `stream:true`만 보낸다.
7. **정적/SPA** — 게이트웨이 ServeDir: `/app`, `/static`, `/icons`,
   `manifest.json`, `favicon.ico`, `sw.js` + `GET /chat` 리다이렉트.
8. **크레이트 배치** — 신규 3개: `lattice-auth`, `lattice-platform`
   (workspace·admin·features·permissions·review·proposals·mcp·
   marketplace·plugins·hooks·registry), `lattice-chat`(채팅
   오케스트레이션 + hybrid cloud lane). 도메인 적합 라우트는 기존
   크레이트 확장(retrieval: memory/brain 읽기, ingest: local_files/
   capture, jobs: index). `RUST_CRATES`(bump/버전일관성) 갱신 필수.
9. **Python 축소** — `LATTICEAI_WORKER_ONLY=1` 프로필이 아니라
   **삭제**가 원칙: keep-set(pts_grok 산출) 밖의 latticeai/
   lattice_brain 모듈과 그 테스트를 지운다. 커버리지 100%는 분모
   축소로 유지하되 arc 단위로 확인. 게이트 파일 10종 동기화
   (mypy files 403경로, setuptools packages, wheel smoke 29모듈,
   MANIFEST, package.json files, product_readiness needle,
   FEATURE_STATUS `_NOT_HTTP_PATHS`, server_app 분해 테스트,
   Release History 테스트, i18n 라우터 목록).
10. **클라이언트/진입점** — SPA·확장·Telegram은 무변경(경로 보존).
    `bin/ltcai.js`·`cli/entrypoint.py`·src-tauri `direct/external`
    토폴로지는 lattice-host 프론트 필수로 재배선. 워커 진입점은
    유지(`server:app`) — 호스트가 스폰한다.

## 검증 규약 (전 WP 공통)

- **캡처-리플레이 패리티**: 삭제 전 Python 구현에서 TestClient로
  라우트별 골든 요청/응답(정상 + 인증거부 + 오류 분기)을 생성해
  `rust/fixtures/http/<family>.json`으로 커밋, Rust 테스트가 리플레이.
  클라이언트가 밟는 ~190 경로는 전 분기, 나머지는 대표 분기.
- **네이티브 증명**: lattice-host `FakeWorker`로 "워커 요청 0건" 단언
  (기존 gateway_mounts.rs 패턴).
- 공유 파일(`rust/Cargo.toml`, `gateway/{mod,mounts}.rs`,
  `app_factory.py`, `pyproject.toml`)은 **통합자(Fable 5)만** 편집.
  각 WP는 자기 크레이트/모듈 파일만 소유하고 배선 노트를 남긴다.
