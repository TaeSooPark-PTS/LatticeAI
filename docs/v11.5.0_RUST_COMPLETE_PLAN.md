# v11.5.0 — Rust Complete (설계 문서)

> 상태: 계획 → 구현 → **출하됨(v11.5.0)**. v11.4.0 Rust Foundation 계획의
> Phase 2·3·4를 한 릴리스로 완결한다. 원칙 불변: **작동하고 증명된
> 조각만 출하하고, Python 서버는 목표 다이어그램의 AI Worker로
> 수렴하되 제거되지 않는다.** 모든 네이티브 경로는 패리티 골든 또는
> 결정표 골든으로 잠근다.
>
> 통합 상태: **완료**. 네 크레이트의 라우터 팩토리는 게이트웨이의
> 리버스 프록시 폴스루보다 앞에 마운트되어 있고(`rust/lattice-host/src/gateway/mounts.rs`),
> 데스크톱은 기본으로 게이트웨이 토폴로지로 뜬다(`src-tauri/src/topology.rs`,
> 안전 밸브 3종 유지). §2a의 CSRF origin 주입과 SSE `X-Accel-Buffering`
> 보강도 배선 완료. §4c(에이전트 루프 오케스트레이션 이식)만 의도적으로
> 남아 있으며, 그 이유는 아래 본문 그대로다.

## Phase 2 — Front Door + 읽기/검색/히스토리 네이티브 + Ingestion 프리미티브

### 2a. 게이트웨이 front-door 기본화 (데스크톱)
- 정찰 확정 사실: 쿠키(host-only)·CSP(`connect-src 'self' http://127.0.0.1:*`)
  ·리다이렉트(전부 상대)는 origin 전환에 안전. **유일한 차단기는 CSRF
  origin 정책이 워커 자신의 포트로 빌드되는 것**(web_runtime.py:42-67,
  csrf.py:154-164 — Host는 프록시가 hop-by-hop으로 제거).
- 해소(Rust만으로): `worker_env`가
  `LATTICEAI_CSRF_TRUSTED_ORIGINS=http://127.0.0.1:{gw},http://localhost:{gw}`
  를 워커에 주입(config.py:170이 이미 파싱). 게이트웨이 SSE 프록시는
  `X-Accel-Buffering: no`를 이벤트 스트림 응답에 보강.
- Tauri는 기본적으로 **게이트웨이 origin으로 항해**(`backend_origin` =
  게이트웨이). `LATTICEAI_DESKTOP_BACKEND_ORIGIN`/`LATTICEAI_DESKTOP_DIRECT=1`
  이면 종전 직결 유지(안전 밸브). e2e: 게이트웨이 경유 스모크 추가.
- 알려진 잔여(문서화): invite-link 절대 URL(Host 재작성), SSO redirect
  기본값, permission UI 기본 URL — 데스크톱 front-door에서 워커 포트를
  가리킴. 영향 좁음(관리자/SSO 경로), FEATURE_STATUS에 명시.

### 2b. 3채널 검색·KG 읽기·히스토리 네이티브 (lattice-retrieval 확장)
패리티 대상(정찰 §6·§7의 명세 그대로):
- `graph_search`: direct 1/rank + relationship 0.75/rank + traverse
  이웃 0.45/rank, score=max 병합, **안정 정렬(동점 삽입순, id 타이브레이크
  없음 — Python 그대로)**, graph_context 축적.
- `relationship_search`: 6-way LIKE, `ORDER BY weight DESC, created_at
  DESC, id ASC`, 양 끝점 스코프 통과 시만 생존, 점수 없음.
- `traverse`: 무방향 BFS, 라운드당 `limit*3` 엣지 캡(라운드 종속성
  포함 재현), visited<limit 게이트, 노드 수화 `updated_at DESC, id ASC`.
- 서비스층 `hybrid_search`(3채널): `weights` 명시=재작성/감쇠 없음,
  None=policy 적용; 기여도 `w * max(score, 1/rank)` 합산; 채널 payload
  에코; POST/GET 비대칭 재현.
- 히스토리 읽기: `_scope_sql`(빈 allowed+no-legacy ⇒ 1=0), 그룹핑
  (`legacy-previous-history` 버킷, updated_at DESC), get_conversation
  (전체 로드 후 필터 — 동일 재현), search(부분일치, "마지막 30그룹"
  슬라이스 그대로).
- 골든: 기존 픽스처 스토어 확장(대화 행 추가) + 새 질의 세트,
  Python 계약 테스트 확장. 게이트웨이 라우트:
  `/rust/search/service-hybrid`, `/rust/graph/{search,relationships,traverse}`,
  `/rust/history`, `/rust/history/{conversations,search}` (라우터 팩토리로
  노출, X5가 마운트).

### 2c. lattice-ingest — Watch · Parse · Chunk · Dedup (단일 작성자 원칙)
- **typed chunking 1:1 포트**(_kg_common/text.py 명세 전부: plain 1200/160,
  markdown 섹션 스택+200자 전방 병합, code 세그먼트 팩킹+1.5x 하드리밋,
  prose 경계 백업 `max(start+1, end-overlap)`, overlap 클램프) +
  chunk id `chunk:{sha256(f"{node}:{i}:{text}")[:24]}` (utf-8 replace).
- 해시 규약: `_clean_text`+sha256(text_hash), content_hash 이원 규약
  (파일=바이트 sha256, 텍스트=`type|uri|text`) 그대로.
- 파일 워치: mtime 폴링 스냅샷(현행 folder_watch 의미론 — OS 워처
  아님)을 Rust 타이머로; 변경 감지 시 **워커의 기존 인제스트 API로
  위임**(`POST /knowledge-graph/ingest` type=note 또는 folder 재스캔
  트리거) — 그래프 쓰기는 계속 Python 단일 작성자. Rust는 감지·파싱
  (txt/md)·청킹·중복 판정까지 수행하고 결과를 검증 가능하게 반환.
- 패리티: 청킹 골든(Python 생성기 — 4전략 × 경계 케이스 · 한/영 ·
  PDF 페이지 오프셋 산술) 완전 일치.

## Phase 3 — Jobs · Events · Scheduler + Context Builder

### 3a. lattice-jobs — 스케줄러 (문서화된 갭의 해소)
- FEATURE_STATUS:179-185 "아무것도 배경 임베드 큐를 몰지 않는다"를
  닫는다: Rust 타이머(기본 60s, env 조절)가 워커의 **신규 additive
  엔드포인트** `POST /api/index/drain`(이번 릴리스에 Python에 추가,
  `IngestionPipeline.drain_vector_queue` 호출, require_user+게이트,
  100% 커버)을 호출. 미완 ingestion job resume도 동일 타이머가
  `GET /api/ingestion/jobs` → 조건부 `/resume`으로 재개(기본 꺼짐,
  `LATTICEAI_JOBS_AUTORESUME=1` 옵트인).
- `/host/jobs` 상태 라우트: 마지막 틱 결과·다음 예정·큐 카운트
  (`vector_jobs` 읽기 전용 카운트는 lattice-core로 직접).
- 이벤트: 틱 결과를 호스트 로그 + `/host/jobs`에 노출(간결·정직).

### 3b. Context Builder 네이티브 (lattice-retrieval 내 모듈)
- `lattice_brain/context.py`의 `ContextAssembler` 포트: approx_tokens
  `(len+3)//4`, 고정 섹션 순서(memories→artifacts→knowledge→notes→recent),
  greedy 예산 절단(`content[:remaining*4]`, 절단 후 재계측 동작 포함)
  — 시임은 네이티브 검색/히스토리 리더로 주입. 골든: 동일 픽스처에서
  Python 어셈블러 출력과 완전 일치. 게이트웨이 `/rust/context/assemble`.
- 문서 생성용 context_builder(B)는 Phase 4 이후로 명시 이월(
  search_for_document_generation 의존).

## Phase 4 — Agent Runtime: Tools · Sandbox · Permission (안전 커널)

**다이어그램의 라벨(Tools/Process/Sandbox/Permission)을 Rust가 소유**하고,
LLM 추론·변이 도구 실행은 워커에 위임(그것이 AI Worker의 정의다).

### 4a. 권한 커널 — 결정표 패리티
- `normalize_mode`(별칭 표 포함), `effective_auto_approve`(모드×도구
  집합×risk×change_class 전 분기), `is_circuit_breaker`(파괴 risk·루트/홈
  경로·rm -rf 변형), `should_stage_proposal`, `plan_requires_approval`,
  `block_reason_for_tool`(우선순위 체인), `classify_tool_call`
  (MUTATING_TOOL_INVENTORY 27종) 전부 포트.
- **결정표 골든**: Python 생성기가 (mode × tool × policy × args)
  그리드 수백 케이스의 판정을 JSON으로 떠서 커밋; Rust와 Python 양쪽
  계약 테스트가 같은 골든을 상시 단언(11.4.0 방식).

### 4b. 도구 샌드박스 — 검증 패리티 + 네이티브 실행(읽기 전용)
- `run_command` 검증기 포트: shlex 분해, 실행경로/allowlist/셸 연산자/
  find·rg 플래그/절대경로·`..`·심링크 이스케이프 규칙, env 치환
  (HOME=AGENT_ROOT, 고정 PATH). **검증 판정 골든**(명령 문자열 그리드)
  완전 일치. 통과한 읽기 전용 명령(pwd/ls/find/cat/head/tail/wc/rg)은
  Rust가 직접 실행(타임아웃 30s·출력 12,000자 캡 동일).
- 파일 도구: `_resolve_path` 의미론(AGENT_ROOT 격리) + read/list 네이티브.
- 게이트웨이 `/rust/agent/preflight`(계획/도구콜 배열 + mode → 판정
  목록)와 `/rust/agent/exec`(커널 통과 읽기 전용 명령만 실행; 그 외
  는 판정과 함께 거부) — 변이는 절대 실행하지 않는다.

### 4c. 루프 위임 — `/rust/agent/run`
- 워커 `/agent`(SSE)로 턴을 위임하되 호스트가 `permission_mode`를
  스탬프하고, 반환 계획에 커널 preflight를 병기해 표면에 제공.
  Python 루프 자체의 재작성은 **명시적 비-목표**(결정 커널이 잠긴
  지금, 루프 이식은 후속 릴리스의 기계적 작업으로 남긴다 — 이유:
  AgentDeps 12개 시임의 실배선 검증 없이 이식하면 증명 없는 재작성).

## 정직한 경계 (FEATURE_STATUS에 그대로 기재)

- Python 서버는 계속 모든 제품 표면을 서빙한다 — front-door는
  데스크톱 기본 + 옵트인 바이너리이며, 네이티브 라우트는 검증된

  도구 실행·그래프 쓰기는 워커 소유(설계상 단일 작성자/AI Worker).
- 에이전트 루프 오케스트레이션의 Rust 이식은 남는다(4c의 이유).
