# v11.5.0 — Rust Complete (Design Document)

> Status: planned → implemented → **shipped (v11.5.0)**. Completes Phases 2, 3,
> and 4 of the v11.4.0 Rust Foundation plan in a single release. Core principle
> unchanged: **ship only working, proven slices, while the Python server
> converges into the target diagram's AI Worker rather than disappearing.**
> Every native path is locked by parity goldens or decision-table goldens.
>
> Integration status: **complete**. Router factories from all four crates are
> mounted ahead of the gateway reverse-proxy fallthrough
> (`rust/lattice-host/src/gateway/mounts.rs`), and Desktop boots into the
> gateway topology by default (`src-tauri/src/topology.rs`, keeping all three
> escape valves). §2a CSRF origin injection and SSE `X-Accel-Buffering`
> reinforcement are wired. Only §4c (agent loop orchestration port) remains
> intentionally open for the reasons documented below.

## Phase 2 — Front Door + Native Read/Search/History + Ingestion Primitives

### 2a. Gateway as Default Front Door (Desktop)
- Recon confirmed: host-only cookies, CSP (`connect-src 'self' http://127.0.0.1:*`), and relative redirects are safe under an origin switch. **The only blocker is CSRF origin policy building against the worker's own port** (`web_runtime.py:42-67`, `csrf.py:154-164` — the proxy strips `Host` as hop-by-hop).
- Resolution (Rust-only): `worker_env` injects `LATTICEAI_CSRF_TRUSTED_ORIGINS=http://127.0.0.1:{gw},http://localhost:{gw}` into the worker (already parsed by `config.py:170`). The gateway SSE proxy adds `X-Accel-Buffering: no` to event-stream responses.
- Tauri navigates to the **gateway origin** by default (`backend_origin` = gateway). `LATTICEAI_DESKTOP_BACKEND_ORIGIN` / `LATTICEAI_DESKTOP_DIRECT=1` keep direct worker connections as escape valves. Added e2e smoke coverage through the gateway.
- Known leftovers (documented): absolute invite-link URLs (`Host` rewrite), default SSO redirect, and default permission UI URL still point to the worker port behind the desktop front door. Narrow impact (admin/SSO paths), recorded in `FEATURE_STATUS`.

### 2b. Native 3-Channel Search, KG Reads & History (`lattice-retrieval` Expansion)
Parity targets (matching recon §6 & §7 verbatim):
- `graph_search`: direct `1/rank` + relationship `0.75/rank` + traverse neighbor `0.45/rank`, `score = max` merge, **stable sort (insertion order on ties, no ID tiebreak — matching Python)**, plus `graph_context` accumulation.
- `relationship_search`: 6-way `LIKE`, `ORDER BY weight DESC, created_at DESC, id ASC`, survives only when both endpoints pass workspace scope, unscored.
- `traverse`: undirected BFS, `limit*3` edge cap per round (reproducing round dependence), `visited < limit` gate, node hydration ordered by `updated_at DESC, id ASC`.
- Service-layer `hybrid_search` (3-channel): explicit `weights` disables rewrite/decay, `None` applies policy; sums `w * max(score, 1/rank)`; echoes channel payloads; reproduces `POST`/`GET` asymmetry.
- History reads: `_scope_sql` (empty allowed + no-legacy ⇒ `1=0`), grouping (`legacy-previous-history` bucket, `updated_at DESC`), `get_conversation` (load-all then filter — reproduced identically), `search` (substring match, preserving the "last 30 groups" slice).
- Goldens: expand the existing fixture store (adding conversation rows) + new query suites + expanded Python contract tests. Gateway routes: `/rust/search/service-hybrid`, `/rust/graph/{search,relationships,traverse}`, `/rust/history`, `/rust/history/{conversations,search}` (exposed via router factories and mounted by X5).

### 2c. `lattice-ingest` — Watch · Parse · Chunk · Dedup (Single-Writer Principle)
- **1:1 port of typed chunking** (full `_kg_common/text.py` spec: plain 1200/160, Markdown section stack + 200-char forward merge, code segment packing + 1.5x hard limit, prose boundary backup `max(start+1, end-overlap)`, overlap clamping) + chunk ID `chunk:{sha256(f"{node}:{i}:{text}")[:24]}` (`utf-8` replace).
- Hash conventions: `_clean_text` + SHA-256 (`text_hash`), dual `content_hash` convention (file = raw byte SHA-256, text = `type|uri|text`) preserved verbatim.
- File watch: mtime polling snapshot (matching existing `folder_watch` semantics — not an OS watcher) on a Rust timer; on change, **delegates to the worker's existing ingest API** (`POST /knowledge-graph/ingest` `type=note` or folder rescan trigger) — Python remains the single graph writer. Rust performs detection, parsing (`txt`/`md`), chunking, and dedup, returning verifiable results.
- Parity: chunking goldens (Python generator — 4 strategies × edge cases, Korean/English, PDF page-offset math) match identically.

## Phase 3 — Jobs · Events · Scheduler + Context Builder

### 3a. `lattice-jobs` — Scheduler (Closing a Documented Gap)
- Closes `FEATURE_STATUS:179-185` ("nothing drives the background embed queue"): a Rust timer (default 60s, env-configurable) invokes a **new additive Python endpoint** `POST /api/index/drain` (calls `IngestionPipeline.drain_vector_queue`, guarded by `require_user` + gate, 100% covered). The same timer can optionally resume incomplete ingestion jobs via `GET /api/ingestion/jobs` → conditional `/resume` (off by default, opt-in via `LATTICEAI_JOBS_AUTORESUME=1`).
- `/host/jobs` status route: last tick result, next scheduled tick, and queue counts (read-only `vector_jobs` count directly via `lattice-core`).
- Events: tick outcomes surfaced in host logs and `/host/jobs` (concise and honest).

### 3b. Native Context Builder (Module inside `lattice-retrieval`)
- Port of `ContextAssembler` from `lattice_brain/context.py`: `approx_tokens` `(len+3)//4`, fixed section order (`memories → artifacts → knowledge → notes → recent`), greedy budget truncation (`content[:remaining*4]` including post-truncation re-measurement) — fed via native search/history readers. Goldens match Python assembler output verbatim on the same fixtures. Gateway route: `/rust/context/assemble`.
- Document-generation `context_builder(B)` is explicitly deferred past Phase 4 (depends on `search_for_document_generation`).

## Phase 4 — Agent Runtime: Tools · Sandbox · Permission (Safety Kernel)

**Rust owns the diagram's Tools / Process / Sandbox / Permission boxes**, while LLM inference and mutating tool execution stay delegated to the worker (by definition of the AI Worker).

### 4a. Permission Kernel — Decision-Table Parity
- Full port of `normalize_mode` (including alias map), `effective_auto_approve` (every `mode × tool_set × risk × change_class` branch), `is_circuit_breaker` (destructive risk, root/home paths, `rm -rf` variants), `should_stage_proposal`, `plan_requires_approval`, `block_reason_for_tool` (priority chain), and `classify_tool_call` (all 27 entries of `MUTATING_TOOL_INVENTORY`).
- **Decision-table goldens**: a Python generator emits hundreds of `(mode × tool × policy × args)` verdict cases to committed JSON; both Rust and Python contract tests assert the exact same goldens continuously (following the 11.4.0 pattern).

### 4b. Tool Sandbox — Validation Parity + Native Read-Only Execution
- Port of the `run_command` validator: `shlex` parsing, executable path / allowlist / shell operators / `find` & `rg` flags / absolute path / `..` / symlink escape rules, and environment sanitization (`HOME=AGENT_ROOT`, fixed `PATH`). **Validation decision goldens** (command-string grid) match verbatim. Allowed read-only commands (`pwd`, `ls`, `find`, `cat`, `head`, `tail`, `wc`, `rg`) execute natively in Rust with the same 30s timeout and 12,000-char output cap.
- File tools: `_resolve_path` semantics (`AGENT_ROOT` isolation) + native read/list.
- Gateway routes `/rust/agent/preflight` (plan/tool-call list + mode → verdicts) and `/rust/agent/exec` (executes only kernel-approved read-only commands; rejects everything else with its verdict) — never executes mutations.

### 4c. Loop Delegation — `/rust/agent/run`
- Delegates turns to worker `/agent` (SSE) while the host stamps `permission_mode` and attaches kernel preflight verdicts to returned plans. Rewriting the Python loop itself is an **explicit non-goal** here (with the decision kernel locked, porting the loop becomes mechanical follow-up work — porting before verifying all 12 `AgentDeps` seams in live wiring would be an unproven rewrite).

## Gates / Verification / Release

- Add 3 new crates (`lattice-ingest`, `lattice-jobs`, `lattice-agent`) to the workspace; every file ≤1,000 lines (target ≤500); existing `fmt`/`clippy`/`test` CI rust job unchanged.
- Python additions (e.g. drain endpoint) preserve 100% statement/branch coverage.
- All 4 golden families (search/history, chunking, context, permission/command decisions) verified bidirectionally (contract pytest + cargo tests).
- Release flow matches 11.4.0: bump 11.5.0 → docs & theme ("Rust Complete") → recapture evidence (13 screenshots + GIF) → artifacts (DMG) → commit & push `main` → green CI.

## Honest Boundaries (Recorded Verbatim in `FEATURE_STATUS`)

- The Python server still serves all product surfaces — the front door is desktop-default plus an opt-in binary, and native routes act as verified alternatives.
- Document parser matrix (`pdf`/`docx`/`xlsx`/`pptx`), embedding production, LLM inference, mutating tool execution, and graph writes remain worker-owned (by design as single writer / AI Worker).
- Porting agent-loop orchestration to Rust remains open (for the §4c rationale above).
