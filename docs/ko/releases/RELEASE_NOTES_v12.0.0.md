# Lattice AI v12.0.0 — Open House (2026-08-18)

> **상태: historical** — 해당 시점의 보존된 릴리스 노트입니다.

11.9.0은 문서에만 존재하던 단일 진입점을 실제로 열었습니다. 12.0.0은 다른 기여자를 초대할 수 있도록 집안을 정돈하는 릴리스입니다. 가장 큰 두 크레이트를 이름 있는 도메인으로 분리하고(순수 이동, 동작 변경 없음), 신규 기여자를 위한 온보딩 문서를 전면 개편했으며, 11.9.0에 남아 있던 네 가지 정직한 공백(honest gaps)을 닫았습니다. 이에 더해 Graph RAG 품질과 속도를 크게 개선하고, **모델에 구애받지 않는(model-agnostic)** 소형 모델 하네스를 추가했습니다. 외부 진입점은 유지됩니다 — `lattice-host`는 **422개 오퍼레이션 / 41개 패밀리**를 제공하며(`POST /mcp`와 폴더 정리 라우트 추가), Python은 **20개 라우트의 AI 워커**(`POST /worker/vector/query` 추가)로 유지됩니다.

## 한 줄 요약

두 대형 크레이트가 도메인별 지도와 함께 정돈되었고, 11.9.0에 기록된 네 가지 공백이 닫혔으며, 미변경 재인덱싱 시간이 33초에서 0.26초로 단축되었고, 0.5B 모델도 에이전트 작업을 끝까지 완수할 수 있습니다. 아직 닫히지 않은 항목은 아래 정직한 고지(Honest Disclosures)에 빠짐없이 기록했습니다.

## 1 · 집안 정돈 — 두 크레이트 도메인 재구조화 및 온보딩 문서

이 릴리스의 최우선 과제는 기능 추가가 아니라 **복잡도 제어**였습니다. 가장 크고 자주 읽히는 두 크레이트를 *각 파일의 목적* 기준으로 재편했습니다. 모든 파일 이동은 동작 변화 없는 순수 `git mv`로 수행되었으며, 골든 테스트와 계약 테스트 스위트로 동일성이 입증되었습니다.

**`lattice-agent` — 6개 그룹, 하나의 규칙: 커널이 결정하고 서피스가 전달한다.** 43개 파일을 `kernel/`(에이전트 루프 및 거절 가능한 모든 의사결정), `parse/`(신뢰할 수 없는 모델 출력 텍스트 → 타입 지정 값), `content/`(실행이 디스크에 쓰려는 바이트), `tools/`(도구 동작과 접근 가능한 영역), `surface/`(인바운드/아웃바운드 HTTP 및 Python 워커 호출 클라이언트), `prompts/`(호출자가 지정하지 않았을 때의 기본 프롬프트)로 이동했습니다. 의존성 화살표는 아래로만 향합니다. `kernel`은 절대 `surface`를 import하지 않으며, `parse`·`content`·`tools`는 절대 `kernel`을 import하지 않습니다. 역방향 화살표가 필요해 보인다면 레이어링이 아니라 인자 목록이 잘못된 것입니다.

**`lattice-platform` — 7개 도메인, 하나의 규칙: 이 크레이트는 제품 서피스다.** 31개의 평면 모듈을 `workspaceos/`(사용자가 작업하는 공간과 구성원), `toolsurface/`(제품이 도달할 수 있는 모든 기능과 카탈로그), `governance/`(자율 동작과 그 앞의 승인 게이트), `adminops/`(설치 환경 운영), `knowledge/`(그래프 콘텐츠가 신뢰 경계를 넘나드는 방식), `modelops/`(실행 가능한 모델 관리), `shell/`(최초 브라우저 접점)으로 옮겼으며, 총 100회의 `git mv`를 수행했습니다. 이 크레이트는 *제안*만 수행합니다. 허용 여부를 결정하는 책임은 `lattice-agent`에, 진실의 원천을 소유하는 책임은 `lattice-core`에 있습니다.

**지도는 문서 안에 존재합니다.** 두 크레이트 모두 크레이트 로컬 `ARCHITECTURE.md`를 제공합니다 — [`rust/lattice-agent/ARCHITECTURE.md`](../../../rust/lattice-agent/ARCHITECTURE.md) 및 [`rust/lattice-platform/ARCHITECTURE.md`](../../../rust/lattice-platform/ARCHITECTURE.md). 각 그룹의 `mod.rs`는 내부에 속해야 할 것, 절대 들어오면 안 되는 것, 유지되어야 하는 불변식을 명시합니다. `ARCHITECTURE.md`가 색인이라면 `mod.rs`는 계약입니다. 두 크레이트의 `src/lib.rs` 하단에는 호환성 맵을 유지해 개편 이전의 모든 `lattice_agent::...` 및 `lattice_platform::...` 경로가 그대로 해석됩니다. 이 맵은 외부 결합 현황의 정직한 목록 역할도 하므로, 호출부를 함께 수정하지 않고는 무엇도 임의로 제거할 수 없습니다.

**기여자 문서를 전면 재작성했습니다.** [`docs/DEVELOPMENT.md`](../DEVELOPMENT.md)는 10분 빠른 시작, **어디에 무엇을 둘 것인가** 표, 각 CI 게이트 실패 원인 가이드를 갖춘 기여자 온보딩 문서로 탈바꿈했습니다. 신설된 [`docs/ROADMAP.md`](../ROADMAP.md)는 남은 공백을 우선순위(`P1`/`P2`/`P3`), 공수, 권장 경로와 함께 추적하며, 이번 릴리스에서 닫힌 항목은 재오픈되지 않도록 완료 표시했습니다.

## 2 · Graph RAG — 품질과 속도

**한국어 인식 검색.** 한국어 조사 제거가 복합 조사를 포괄하는 2단계로 동작해, 같은 명사의 다양한 조사 결합형이 동일한 후보에 도달합니다. 근거 게이트(grounding gate)는 단순 어휘 일치만으로 답변을 정당화하지 못하도록 차단하며, 포함 중복 제거(containment deduplication)는 긴 청크와 그 안의 짧은 청크가 이중 집계되는 문제를 방지합니다.

**방향성 타입 엣지.** 추출 파이프라인이 이제 어휘 정의에만 머무르던 `PART_OF`와 `CONTRADICTS` 엣지를 실제로 **생성**합니다. 근거는 관계 자체에 분류·저장되어 해당 관계가 동사구에서 도출되었는지 동시 출현에서 도출되었는지 기록합니다.

**문서 목차(Section Tree) 구성.** 타입 청커는 이미 각 청크의 `heading_path`(예: `Architecture > Storage`)를 추적하고 있었지만, 12.0.0 이전에는 청크 메타데이터에 머물러 있었습니다. 이제 이 개요가 그래프 내 트리로 투영됩니다: `Document ← part_of ─ Section ← part_of ─ Section`, 그리고 `Section ─ has_chunk → Chunk`. 스키마를 확장하지 않고도 "이 사실이 어느 섹션에서 나왔는가?"와 "그 섹션에 다른 무엇이 있는가?"에 모두 답할 수 있습니다(`Section` 노드와 `PART_OF`/`HAS_CHUNK` 엣지는 이미 분류 체계에 존재했고 기록기만 없었습니다). 제목이 없는 문서는 인위적인 "untitled" 섹션을 만들지 않습니다. 실측 결과 **555개 트리플 중 549개**가 섹션 출처를 보유합니다.

**임베딩 자동 감지.** 실제로 다운로드된 임베딩 모델이 존재하면 자동으로 채택할 수 있고, 없을 때는 해시 폴백을 **폴백(fallback)으로 정직하게 표기**합니다. 벡터 식별자 `(model, dim)` 필터링을 검증해 서로 다른 임베딩 공간이 조용히 뒤섞이지 않도록 했습니다.

[`docs/kg-schema.md`](../kg-schema.md) 스키마 문서에 `Section`, `HAS_CHUNK`, `PART_OF`, `CONTRADICTS` 사양이 명시되어 있습니다.

**속도 향상은 불필요한 작업 제거에서 나왔습니다:**

- **미변경 재인덱싱: 33초 → 0.26초.** 별도 테이블을 만들지 않고 `ingestion_provenance.metadata_json`에 파일별 지문(경로 + 크기 + mtime + 콘텐츠 SHA-256)을 저장합니다. SHA-256은 크기나 mtime이 바뀐 경우에만 계산합니다. 변경되지 않은 파일을 다시 읽고 청킹·임베딩하던 낭비 비율이 `1.00`에서 `0.00`으로 떨어졌습니다.
- **초기 인덱싱: 25.8초 → 7.2초.**
- **드레인 처리량: ~66 → ~1,300건/초.** 임베딩 연산을 쓰기 트랜잭션 *바깥*으로 이동해 모델을 기다리는 동안 저장소 쓰기 락을 점유하지 않도록 했습니다.
- **991건 백로그 처리: 40분 → 15.3초.** 적응형 스케줄러가 대기 작업이 쌓이면 더 적극적으로 폴링하고 유휴 상태에서는 백오프합니다.
- **증분 HNSW 추가 + 실시간 검색 활용.** `LATTICEAI_VECTOR_INDEX=hnsw` 설정 시 워커 사이드카가 후보를 공급하고 Rust가 전수 검색과 **완전히 동일한 코사인 메트릭**으로 재점수화합니다(근사 리콜, 정확한 정렬). 결과에는 `hnsw+rescore` 인덱스명이 기록되며 실패 시 명시적 사유와 함께 전수 검색으로 폴백합니다. **기본값은 여전히 `brute`**입니다(정확하며 이전 릴리스와 바이트 단위 호환).
- **`vault-watch`의 미변경 diff 건너뛰기.** 수정되지 않은 노트는 더 이상 재수집하지 않습니다.

**삭제된 파일 정리(Pruning).** 기존 증분 인덱싱은 사라진 파일 수만 *집계*하고 노드는 유지했습니다. 노드 삭제는 인덱싱의 부수 효과가 아니라 제품 차원의 결정이기 때문입니다. 이제 명시적 진입점 `POST /api/ingestion/folder/prune`이 추가되어 `confirm` 없이는 드라이런만 수행하고, 확인 시에만 `delete_document_tree`(양방향 엣지 정리)로 노드를 제거합니다. UI에도 "Prune deleted files (N)" 카드 액션이 추가되었습니다. `PART_OF` 엣지가 남던 11.7 함정을 피하기 위해 여기서는 `delete_node`를 절대 사용하지 않으며, 정리 후 고아 엣지 0건을 검증했습니다.

## 3 · 모든 소형 모델을 위한 하네스

이 제품은 기기에 맞는 어떤 로컬 모델에서도 동작해야 하지만, 0.5B 모델은 단순히 작은 70B가 아닙니다. 종종 **JSON 도구 호출 계약 자체를 전혀 만족하지 못합니다**. 해법은 네 부분으로 구성되며, 어느 부분에도 모델 이름을 하드코딩하지 않았습니다. 모델별 편법 분기는 여전히 금지됩니다.

**`guided` 모드 — JSON 요구 자체를 제거.** `standard`와 `compact`에 더해 새로운 `guided` 다이얼은 각 단계를 마이크로 턴으로 분해합니다. 실행의 실시간 **번호 매긴 카탈로그**에서 번호 하나를 고른 뒤 필수 인자마다 한 턴씩 응답합니다(`path`는 한 줄, `content`는 자유 텍스트 — JSON 이스케이프 불필요). **하네스가 액션 구조체를 직접 조립**해 `perform_action`에 전달하므로, 모든 모드와 동일한 게이트 체인, 루프 가드, 쓰기 전 스냅샷, `sanitize_write_content`가 그대로 유지됩니다. 검증 역시 닫힌 `PASS`/`FAIL` 질문과 한 줄 사유로 수행되며 JSON 판정과 동일한 근거·커버리지 게이트를 거칩니다. 거버넌스 지름길은 없으며 생략된 것은 오직 JSON 문법뿐입니다.

**측정 기반 프로빙 — 추측 대신 실측.** 모델 로드 시 고정된 2개의 프로브 프롬프트(약한 모델의 JSON 문자열을 깨뜨리는 줄바꿈과 따옴표를 포함한 액션 객체 포함)를 전송하고 **루프 자체 파서**로 채점해 다이얼을 결정합니다: 무수정 파싱 → `standard`, 복구 파싱 → `compact`, 파싱 불가 → `guided`. 판정 결과는 모델 ID와 **크레이트 버전** 기준으로 캐싱됩니다. `LATTICEAI_AGENT_PROFILE`은 여전히 모든 설정을 우선하며, `LATTICEAI_AGENT_PROBE=0`은 프로빙을 비활성화합니다. 크기 정규식은 프로빙 불가 시 폴백 사전값으로만 남습니다.

**실행 중 자체 하향 조정 — 오직 하향만 허용.** 프로빙은 작은 합성 프롬프트를 시험하지만 실제 작업은 더 어렵습니다. `standard` 또는 `compact`로 **측정**된 실행이 유효한 진전 없이 포맷 예산을 소진하면(예: 프롬프트 예시 복사 또는 파싱 가능한 액션 미생성) 스스로 `guided`로 하향 전환해 작업을 완수합니다. 세 가지 가드가 적용됩니다: 다이얼이 실측된 값이어야 하며, 이미 `guided`가 아니어야 하고, 아직 실행 증거가 생성되지 않았어야 합니다. 상향 승격은 절대 일어나지 않습니다.

**통합 카탈로그 — 세 서피스를 하나의 메뉴로.** 네이티브 도구, `mcp.<tool>`, `skill.<name>`이 하나의 번호 매긴 메뉴, 하나의 인자 시그니처 집합, 하나의 디스패치 결정을 공유합니다. 실행 수준 정책이 이미 부여된 이름은 더 엄격한 **네이티브 경로**를 따르고, 그렇지 않은 이름은 호스트 카탈로그에 도달하며 MCP 디스패치는 `POST /mcp`와 **동일한** 거버넌스 검사를 거칩니다. 거버넌스 거부, 알 수 없는 도구, 누락된 도구 서피스는 우회 대신 도구 오류를 반환합니다.

**심(Seam) 레벨 구조적 프리필.** `Completion::prefix`는 생성 텍스트가 지정된 접두사로 *시작하도록* 강제합니다(`compact`는 `{"thoughts": "` 전송). 서문, 마크다운 펜스, `<|channel|>` 프레임을 사후 복구에만 의존하지 않고 생성 시점에 원천 차단합니다. 워커는 생성 마커 뒤에 접두사를 프리필하고 반환 텍스트가 반드시 해당 접두사로 시작함을 보장합니다. 토큰 단위 JSON 문법 제약은 **의도적으로 제외**했습니다. 단일 MLX 러너 위에서 토크나이저 인식 증분 파서와 토큰당 Python 콜백이 필요한 반면, `guided`는 JSON 자체를 요구하지 않음으로써 토큰당 오버헤드 0으로 동일한 보장을 달성합니다.

**실증 사례.** Qwen 0.5B가 `guided` 모드에서 3.9초 만에 실제 파일을 생성하며 **DONE**에 도달했습니다. 이 크기 급의 모델이 Lattice AI에서 종단간 에이전트 실행을 완수한 첫 사례입니다.

**모델 매트릭스.** 동일 벤치마크 스위트를 여러 크기 모델에서 실행한 결과가 릴리스 게이트 아티팩트로 남습니다. 3개 모델 대상 pass12 실측 결과:

## 4 · 닫힌 정직한 공백 4건, 남은 2건

11.9.0의 정직한 고지에 나열된 네 항목이 이번에 닫혔습니다:

- **복원 후 재시작 불필요.** 저장소가 이제 세대 에포크(generation epoch)를 추적합니다. 복원이 에포크를 증가시키면 캐시된 풀 커넥션이 즉시 만료 상태로 감지·폐기되어, 프로세스를 재시작하지 않아도 다음 읽기에서 복원된 바이트를 바로 확인합니다.
- **`/setup/install`의 실제 설치 실행 — 항목별 명시적 동의 엄수.** `brew`/`pip`/`uv` 명령은 대상 항목이 **서버 파생 허용 목록(allowlist)**에 속할 때만 실행됩니다. 목록 외 항목은 거절됩니다. **수동 모드가 여전히 기본값**이며, 실행에는 항목별 사용자 명시 동의가 필요합니다.
- **`POST /mcp`의 OpenAPI 계약 편입.** 마운트 테이블과 OpenAPI 스펙 모두에 단일 JSON-RPC 엔벨로프 오퍼레이션으로 선언되었습니다. 네이티브 마운트이므로 프로세스 내에서 직접 처리되며 워커로 프록시되지 않습니다.
- **포인터 도구 명시적 선언.** `pyproject.toml`이 6개 `pyautogui` 포인터 도구의 설치 경로로 `pip install "ltcai[pointer]"`를 선언합니다. 기본 설치에서는 여전히 `capabilities.pointer_tools=false`를 정직하게 보고하며, 기능이 미선언 상태였던 공백을 해소했습니다.

의도적으로 열어 둔 두 항목은 그대로 유지·문서화됩니다: **HNSW는 선택 옵션(opt-in)**이며 검색 기본값은 `brute`이고, **`watch`는 파일을 자동 삭제하지 않습니다**(위 명시적 prune 경로를 통해서만 정리).

## 5 · 프론트엔드 하드닝

- **앱 전역 `ErrorBoundary`.** 라우트별 및 대형 패널 주변에 배치해 단일 패널 오류가 전체 화면을 하얗게 만들지 않고 인라인 "다시 시도" 폴백으로 안전하게 축소됩니다.
- **Act / Brain 하위 라우트 지연 분할.** 최초 렌더링 시 열지 않은 화면의 코드를 전송하지 않습니다.
- **더 넓은 사전 미리보기 패턴.** 권한 모드 변경 시 달라지는 항목의 diff를 미리 보여주며, 위험 기능 토글은 명시적 확인을 요구합니다.
- 번들 크기는 **104.3 KiB / 150 KiB 예산** 이내로 유지됩니다.

## 6 · 기존 버그 수정

- **RAG 인용 지침이 에이전트 프롬프트로 누출되던 문제.** 채팅 인용 규칙이 에이전트 턴에 섞여 들어 모델이 도구 호출 대신 인용을 출력하던 문제를 수정했습니다.
- **모델 로딩 이름 로스터 게이트.** 로더의 허용 목록 검사가 Qwen AWQ 모델 로딩 자체를 막던 문제를 제거했습니다.
- **복사 가능한 작업 예시(Worked examples).** 약한 모델은 프롬프트 내 가장 가까운 완성 패턴을 그대로 이어 쓰는 경향이 있습니다. `write_file`의 `content`가 크레이트 내장 프롬프트 예시 상수와 정확히 일치하면 루프가 `COPIED_EXAMPLE`을 기록하고 **아무것도 쓰지 않습니다**(fail-closed). 비교 대상이 크레이트 소유 상수이므로 정상 사용자 답변이 오탐 거절되지 않습니다.
- **`<|channel>` 단일 파이프 제어 프레임 누출.** 닫는 파이프가 빠져 파서를 통과해 응답 본문에 섞이던 변형 프레임을 차단했습니다.

## 정직한 고지 (Honest Disclosures)

- **소형 모델의 *콘텐츠 품질*은 여전히 fail-closed 게이트에 걸립니다.** 요청된 파일을 쓰고 DONE에 도달하는 기계적 실행은 `guided` 모드에서 안정적이지만, 빈약한 요약이나 부실한 설명은 비평가(critic)가 `FAILED`/`NEEDS_REVIEW`로 거부할 수 있습니다. 이는 조용한 실패가 아니라 가시적인 실패입니다.
- **`api_key` 클라우드 경로는 목(mock) 검증만 수행합니다.** 무과금 정책에 따라 유료 라이브 호출 없이 계약 테스트만 유지하며, 라이브 검증은 무과금 `cli_oauth`(`agy`/`grok`)를 대상으로 합니다.
- **macOS DMG는 ad-hoc 서명(= 미서명) 상태입니다.** 이전 릴리스와 동일하며 첫 실행 시 Gatekeeper 허용 단계가 필요합니다.
- **벡터 검색 기본값은 `brute`입니다.** `hnsw`는 opt-in(`hnsw+rescore`)이며 실패 시 명시적 사유와 함께 `brute`로 폴백합니다.
- **`watch`는 자동 삭제하지 않습니다.** 누락 파일만 보고하며 제거는 명시적 prune(`dry-run` → `confirm`)으로만 수행됩니다.
- **크레이트 재구조화는 순수 이동이었습니다.** 도메인 경계를 그렸다고 모든 크로스 도메인 결합이 제거된 것은 아니며, 남은 4건의 경계 간 결합은 `lattice-platform` 아키텍처 지도에 명시되어 있습니다.

11.9.0에 남아 있던 항목들도 그대로 문서화되어 있습니다 — 90% 라인 커버리지 하한, 멀티모달 이미지/비디오 HTTP 진입점 부분 미노출, Self-Model `open_keys`의 `pending` 한정 및 UI 화면 부재, 추출 `refiner` 부재, 소유자 없는 리뷰 이벤트 무음 처리, KG-API 수집의 텍스트 전용 제약, 리뷰 변경의 2회 저장소 사이클 소요. Telegram 브리지와 SSO OIDC 로그인/콜백은 11.6.0부터 제거된 상태입니다. 남은 공백의 우선순위와 권장 경로는 [`docs/ROADMAP.md`](../ROADMAP.md)에서 관리합니다.
