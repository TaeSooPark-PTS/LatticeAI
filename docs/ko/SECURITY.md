## 보안 모델

Lattice AI는 로컬 우선(local-first) Digital Brain입니다. 사용자 지식, 대화 컨텍스트, 지식 그래프 데이터, 아카이브를 기본값으로 로컬에 보관하며 모든 외부 통신 경로를 명시적으로 제어합니다.

11.6.0부터 제품 서버는 `lattice-host`(Rust)이며 Python 패키지는 루프백을 통해서만 접근되는 AI 워커로 동작합니다. **11.8.0에서는 해당 워커를 28개 라우트에서 19개로 축소**하여 트리 내 어디에서도 호출되지 않는 9개 라우트를 라우트·구현·allowlist 항목·게이트웨이 테이블까지 종단간 제거했고, 게이트웨이가 이를 더 이상 전달하지 않음을 부정 테스트(negative test)로 검증합니다. 호출되지 않는 라우트도 공격 표면이므로 제품이 실제로 요청하는 경로만 응답하는 최소한의 워커를 유지합니다. 11.9.0은 표면을 넓히지 않았으며(`/worker/sysinfo`에 `capabilities`와 `python_version` 필드만 추가), **12.0.0은 명확한 사유로 1개 라우트를 추가했습니다**: `POST /worker/vector/query`는 `LATTICEAI_VECTOR_INDEX=hnsw` 옵트인 시 네이티브 정확 재스코어링을 위한 후보 ID만 반환하며 쓰기 작업을 전혀 수행하지 않고, 기본 `brute` 백엔드는 이를 호출하지 않습니다. allowlist는 총 **20개**이며 워커 자체 프로필에서 생성되어 양측에 고정됩니다.

12.0.0의 크레이트 도메인 재구성은 어떤 신뢰 경계도 이동시키지 않습니다. `lattice-agent`는 6개 그룹, `lattice-platform`은 7개 도메인으로 나뉘었지만 실행 허가 판단은 여전히 동일한 커널이 담당하고, 그래프 쓰기는 동일한 단일 `GraphWriter`가 소유하며, 게이트웨이도 allowlist 외 모든 요청을 그대로 거부합니다. 이 재구성이 보안 문서에 주는 이점은 보안 핵심 코드의 주소가 명확해졌다는 점입니다. 거부는 `lattice-agent`의 `kernel/`, 신뢰할 수 없는 모델 텍스트 처리는 `parse/`, 실행 중 디스크에 쓰려는 모든 바이트는 `content/sanitize`를 거칩니다.

### 인증 및 세션

- 비밀번호는 `scrypt` 해싱을 사용합니다.
- 세션 쿠키는 `HttpOnly` 및 `SameSite=Lax`이며, 비루프백/공개 배포에서는 `Secure`도 함께 설정합니다.
- 세션 토큰은 로컬에 SHA-256 해시로만 저장되며, 삭제되거나 비활성화된 계정은 다음 요청에서 기존 세션이 즉시 무효화됩니다.
- **워커는 세션 파일을 영구 캐시하지 않고 재조회합니다 (11.8.0).** `sessions.json`의 유일한 쓰기 주체는 `lattice-auth`이며 워커는 읽기만 수행합니다. 과거에는 부팅 시 1회만 로드해 이후 발생한 로그인이 누락되는 문제가 있었으나, 이제 캐시 미스 시 포기하기 전에 파일을 다시 읽습니다. 토큰 추측 폭주가 디스크 읽기 폭주로 이어지지 않도록 파일의 `mtime_ns`/`size`가 변하지 않으면 재읽기를 생략하고, 변경 시에도 맵 락 아래에서 초당 최대 1회 파싱으로 스로틀링합니다. 이는 유효한 세션만 인식되게 하며 만료되거나 미등록된 토큰은 재읽기 후에도 동일하게 실패합니다.
- POSIX 파일시스템에서 로컬 데이터 디렉터리는 권한 `0700`, 원자적 JSON/세션 파일은 권한 `0600`으로 생성됩니다.
- 엔터프라이즈 SSO 경로는 명시적 설정 경로입니다.
- 초대 인증은 HMAC 서명, 만료 시간 제한, 서버 바인딩이 적용됩니다. 단순 `authorized=true` 쿠키로는 접근할 수 없으며, 공개 모드에서는 내장 기본 코드로 초대 게이트를 시작하지 않습니다.

### 파일, 워크스페이스 및 아카이브 안전성

- 업로드 파일은 지원하는 형식에 대해 시그니처 검증을 수행합니다.
- 업로드된 블롭은 로컬 데이터 디렉터리 하위에 저장됩니다.
- **사용자별 `AGENT_ROOT` 격리**: 에이전트 워크스페이스 경로는 `IsolatedRootSpec` 및 `resolve_isolated_agent_root`(`lattice-agent::tools::sandbox`, `LoopRoutesState::isolated`)를 통해 서버 측에서 도출되어 `(user_id, tenant_id, workspace_id)` 단위로 분리됩니다. 공유 워크스페이스 경로는 워크스페이스 멤버십 인가기가 검증하지 않으면 fail-closed(`workspace_access_denied`)로 차단됩니다.
- **`.latticebrain` 아카이브 암호화 및 무결성 검증**: Rust(`lattice-platform::knowledge::portability::{archive, crypto}`)에서 구현되어 있으며, 암호 문구 아카이브는 RFC 7914 `scrypt`(`SHA-256` PBKDF2 + Salsa20/8)로 키를 유도하고, 수신자 봉인 서브그래프 번들은 X25519 + HKDF-SHA256을 사용하며, 페이로드는 상수 시간 MAC 검증(`ct_eq`)이 포함된 Encrypt-then-MAC(`SHA256-CTR` + `HMAC-SHA256`)으로 보호합니다.
- 잘못된 암호 문구, 위변조, 미지원 아카이브 버전, ZIP 경로 탐색(`validate_zip_entries`)은 모두 fail-closed로 실패합니다. 내보내기, 검사, 검증, dry-run 복원, 확인된 복원(`confirm: true`), 가져오기 경로 모두 게이트와 감사 로그가 적용됩니다.
- **복원은 실행 중인 프로세스에 즉시 반영됩니다 (12.0.0).** 스토어가 세대(generation) 에폭을 관리하며 복원 시 이를 증가시킵니다. 이전 세대에서 열린 풀 커넥션은 다음 체크아웃 시 만료되어 닫히고 이후 읽기는 즉시 복원된 바이트를 보게 되어, 과거의 "복원 후 재시작" 공백 구간이 제거되었습니다.
- **지식 삭제는 별도의 확인 절차를 거칩니다.** 증분 인제스트는 사라진 파일 수만 집계하고 노드는 유지합니다. `POST /api/ingestion/folder/prune`은 `confirm` 없이는 계획만 보고하고, `confirm`이 주어지면 `GraphWriter::delete_node`(`delete_node_subgraph`)와 통합된 `delete_document_tree`를 통해 양방향 엣지(`PART_OF` 포함), 청크, 벡터, 고아 `Source` 노드, BM25 통계, 출처를 함께 정리하여 댕글링 참조를 남기지 않습니다. 어떤 정리 경로도 디스크 파일을 삭제하지 않습니다.
- **저장소 및 산출물 위생**: `/scratchpad/`, `*.db-wal`, `*.db-shm`는 `.gitignore`에 제외되어 있으며, 과거 `scratchpad/` 아래 추적되던 검증 산출물은 Git 추적과 워킹 트리에서 제거되었습니다. GitHub Actions 워크플로는 서드파티 `uses:` 참조를 불변 커밋 SHA로 고정하며, macOS 릴리스 빌드는 서명 시크릿이 구성되면 Developer ID 서명 및 공증(notarization)을 수행하고 미구성 시 ad-hoc 서명과 SHA-256 체크섬 검증으로 폴백합니다.

### 에이전트 및 도구 안전성

- `AgentRuntime` 미리보기/준비 점검은 도구를 실행하지 않으며, 자동 승인 대상이 아닌 계획은 명시적인 사람 승인이 필요합니다.
- 상태 변경 도구는 거버넌스 인벤토리(`MUTATING_TOOL_INVENTORY`)에 전수 등재되며 각 도구는 제안 기반 거버넌스 대상이거나 명시적 예외로 관리되고, 릴리스 게이트가 이를 검증해 새 변경 도구가 거버넌스를 우회할 수 없습니다. 기존 파일 수정·삭제는 원본 콘텐츠 해시를 기록하고 원자적 적용 직전에 재검증하는 변경 제안을 거쳐 동시 충돌 수정 시 덮어쓰지 않고 fail-closed로 중단됩니다.
- 에이전트 검증기(verifier)는 fail-closed로 동작하여 검증할 수 없거나 실패한 결과는 성공으로 보고하지 않고 검토 대기(`NEEDS_REVIEW`) 상태로 전환합니다.
- **`guided` 프로필은 JSON 요구만 제거하며 보안 게이트는 유지합니다 (12.0.0).** 툴콜 계약을 유지하지 못하는 소형 모델은 번호 메뉴와 턴당 1개 인자 입력을 거치지만, 하네스가 액션을 조립해 모든 프로필이 공유하는 동일한 `perform_action` 경로로 전달하므로 게이트 체인, 루프 가드, 쓰기 전 스냅샷, `sanitize_write_content`, 폐쇄형 PASS/FAIL 검증이 동일하게 적용됩니다.
- **루프는 자신의 프롬프트를 실행하지 않습니다.** 크레이트 내부의 예시 상수(worked-example)를 그대로 복사한 `write_file`은 `COPIED_EXAMPLE`로 기록되어 어디에도 쓰이지 않으며, guided 답변에서 반향된 지시문은 제거됩니다.
- `ToolRegistry`는 디스패치, 권한, 진단, 직접 HTTP/MCP 정책 게이트, MCP 설치 상태를 소유합니다.
- 공유 에이전트/플러그인 레지스트리와 그래프 큐레이션은 관리자가 관리하며, 레지스트리 조회 시 비밀 형태 설정 값은 마스킹됩니다.
- MCP 그래프 호출과 실시간 프레즌스는 인증된 신원과 활성/허용 워크스페이스에 바인딩되며, MCP 환경 변수 값은 절대 반환되지 않습니다.
- 지식 그래프 스코프 조회는 프로젝션/쿼리 오류 시 fail-closed로 실패합니다. 스코프가 불명확한 노드는 비공개이며 레거시 전역 읽기는 명시적인 `include_legacy_global` 호환성 옵션이 필요합니다.
- MCP 및 플러그인 실행은 로컬 파일시스템/문서 도구를 호출할 수 없으며, 해당 도구는 전용 스코프 바인딩 승인 토큰 엔드포인트가 필요합니다. 플러그인은 설치된 매니페스트에 명시 선언된 도구만 호출할 수 있습니다.
- 실시간 SSE 연결은 전달 직전 세션과 워크스페이스 멤버십을 재검증하며, 멤버십 회수 이전에 큐에 쌓인 이벤트에도 동일하게 적용됩니다.
- 명령/파일 도구는 해당되는 경우 샌드박스 및 유일성 검사를 강제합니다.
- 명령 도구는 고정된 실행 파일 allowlist와 정제된 환경을 사용하며, 인터프리터 명령, 실행 경로 직접 지정, 경로 탐색, 심볼릭 링크 탈출, ripgrep 전처리기, `find`의 변경/실행 플래그를 거부합니다.
- 비밀 값 형태는 로그, 감사 페이로드, 보안 내보내기, 프론트엔드 미리보기, 훅 패킷 이전에 중앙에서 마스킹됩니다.
- 컴퓨터 스크린샷/상태, 지식/Obsidian, 채팅 네트워크 상태 도구는 각각 선언된 정책·기능·동의·스코프 검사를 통과해야 합니다.
- 권한 요청은 비공개 파일 권한으로 원자적으로 기록됩니다. 외부 알림에는 토큰 힌트와 선택적 검토 UI 링크만 포함되며 전체 승인 토큰은 포함되지 않습니다. **11.9.0부터 로컬 승인 토큰이 `LocalApprovals`로 통합**되어 신뢰 소유자가 승인한 폴더 인제스트 토큰도 `/permissions/approve`에서 일관되게 처리됩니다.

### 11.8.0에서 삭제된 항목과 보안 약화가 아닌 이유

11.8.0에서는 이름이 보안 제어처럼 보이지만 실제로는 아무것도 강제하지 않던 여러 Python 헬퍼(`hash_password`/`verify_password`, `check_ip_rate_limit`, `configure_trusted_proxies`, `client_ip`, `bytes_match_extension`)를 제거했습니다. 비밀번호 검증, 속도 제한, 신뢰 프록시 해석, 클라이언트 IP 도출은 11.6.0에서 프론트 도어가 Rust로 이전될 때 모두 `lattice-auth`와 게이트웨이로 넘어갔고 Python 워커에는 호출자가 남아 있지 않았습니다. 도달 불가능한 중복 구현을 제거함으로써 향후 유지보수자가 잘못된 코드만 보강하는 실수를 방지합니다.

실제 보안을 지탱하는 가드는 모두 그대로 유지되었습니다. 프록시된 워커 쓰기의 CSRF origin 가드, 디코드·연산 전 인증, 업로드 시그니처 검사, Rust 커널의 모드 불변 서킷 브레이커, 모든 네이티브 쓰기 경로의 `sanitize_write_content`, 그리고 커밋된 워커 allowlist(당시 19개, 12.0.0의 벡터 쿼리 시임 추가 후 20개 — 삭제된 9개 라우트가 전달되지 않고 `404`로 응답함을 테스트로 검증)는 변경 없이 작동합니다.

### 외부 통신

기본 텔레메트리는 없습니다. 토큰이 존재한다는 이유만으로 프롬프트, 파일, 그래프 내용, 아카이브가 장비 외부로 나가지 않습니다.

외부 통신은 명시적 설정과 사용자/관리자 실행이 필요합니다.

- 클라우드 모델 호출
- 모델 다운로드
- Brain Network 피어 교환
- Docker/Postgres 스케일 설정
- 업데이트 확인
- 마켓플레이스 또는 원격 레지스트리 새로고침

**클라우드 턴은 감사 기록과 제안 단계를 거치며 몰래 저장되지 않습니다 (11.9.0).** 모든 클라우드 턴은 공급자를 호출하기 *전에* 공급자·모델·에스컬레이션 사유만 담은(본문 미포함) `cloud_egress` 기록을 남깁니다. 클라우드 답변에서 추출된 지식은 Review Center의 `kg_cloud_expansion` 제안으로 임시 보관되며, 사람이 승인하거나 명시적으로 `auto_commit`(기본값 꺼짐)을 켠 경우에만 그래프에 반영됩니다.

**두 가지 인증 모드(그중 하나는 과금 없이 실환경 검증 완료).** `api_key`는 OpenAI 호환 어댑터이며 과금 예산 없이 목 서버 대상 계약 테스트를 수행했습니다. `cli_oauth`는 로컬에서 OAuth 인증된 CLI(Antigravity `agy` → `gemini-3.7-flash`, `grok` → `grok-4.6`)를 중립 임시 작업 디렉터리와 120초 타임아웃으로 실행하며 API 과금 없이 실환경 검증을 완료했습니다. 해석 우선순위는 `cloud_provider.json` → 환경 변수 키 → `agy` → `grok` → 없음입니다. 요청 단위의 `network_mode: "local_only"`는 항상 에스컬레이션 정책(`auto` 기본 / `manual` / `always`)보다 우선합니다.

`POST /mcp`의 MCP 표면은 호스트 위에서 동작하는 실제 Streamable-HTTP JSON-RPC 서버이며 **12.0.0부터 단일 JSON-RPC 봉투 오퍼레이션으로 OpenAPI 제품 계약 안에 포함**되었습니다. 거버넌스 거부는 JSON-RPC 오류로 반환됩니다. 비인가 우회 문이 아니며, 에이전트 루프 자체도 자체 카탈로그에 거버넌스가 없는 `mcp.<tool>`을 호출할 때 `POST /mcp`와 동일한 거버넌스 검사를 거칩니다. 루프가 직접 거버넌스하는 도구 이름은 더 엄격한 커널 네이티브 경로를 탑니다.

웹 페이지 캡처는 추가로 공인 IP를 해석·고정(pin)하고, 사설/예약 IP 대역을 거부하며, 모든 리다이렉트를 재검사하고, 프록시 환경 변수를 무시하며, 텍스트 콘텐츠를 최대 4 MiB까지만 스트리밍합니다.

### 보안 민감 환경 변수

| 변수 | 필수 여부 | 용도 |
| --- | --- | --- |
| `LATTICEAI_PERMISSION_UI_URL` | 선택 | 권한 검토 UI 기본 URL(승인 토큰은 절대 첨부하거나 전송하지 않음) |
| `LATTICEAI_REQUIRE_AUTH` | 선택, 루프백 기본 꺼짐 | 로컬 모드에서도 인증 강제(공개 또는 비루프백 바인딩 시 자동 강제) |
| `LATTICEAI_INVITE_GATE_ENABLED` | 선택, 기본 꺼짐 | 무제한 회원가입을 열지 않고 초대 기반 온보딩 활성화 |
| `LATTICEAI_INVITE_CODE` | 초대 게이트 활성화 시 권장 | 운영자가 생성한 무작위 초대 코드(미지정 시 설치별 고유 비공개 값을 자동 생성·영속화하며 공용 기본값은 없음) |

## 공개 배포 가이드

Lattice AI를 `localhost` 외부에 노출할 경우:

1. `LATTICEAI_MODE=public`으로 설정하세요.
2. 일반 회원가입을 닫아 두세요. 초대 온보딩이 필요하면 초대 게이트를 켜고 무작위 비공개 `LATTICEAI_INVITE_CODE`를 설정하거나 영구 스토리지에 자동 생성된 설치별 시크릿을 유지하세요(공용 기본값 없음). 유효한 서명 초대는 해당 회원가입 요청 1건만 인가하며 서명 없는 직접 `/register` 호출은 계속 차단됩니다. SSO JIT 계정 생성도 일회성 OIDC state·nonce·PKCE 트랜잭션에 서버 측 바인딩된 동일한 초대 클레임이 필요하며, 기존 활성 SSO 계정은 새 초대 없이 계속 로그인할 수 있습니다.
3. 앱 앞단에 HTTPS를 배치하세요.
4. 영구 스토리지(persistent storage)를 마운트하세요.
5. 사용 전 CORS, 인증, 속도 제한, 그래프 노출 설정을 점검하세요.

## 알려진 제한 사항

- 로컬 파일 보안은 사용자의 OS 계정, 디스크 암호화, 백업 정책에 의존합니다.
- 클라우드 모델 프롬프트는 사용자가 해당 공급자를 선택한 이후 해당 공급자의 정책을 따릅니다.
- 신뢰된 로컬 관리자는 Lattice AI 외부에서 로컬 파일과 프로세스 메모리를 검사할 수 있습니다.
- MLX/Hugging Face 모델 다운로드: `scripts/verify_hf_model_registry.py`는 가중치를 받지 않고 Hub 메타데이터를 정적 검증하며 `EmbeddingIndexContract`는 `model_revision`을 기록하지만, `latticeai/services/model_runtime/download.py`(`_call_hf_hub_download`)와 `latticeai/core/embedding_providers/text.py`(`from_pretrained`)는 아직 모든 다운로드 경로에 불변 Hub 커밋 `revision=` 기본 고정을 적용하지 않았습니다([docs/SECURITY_AUDIT.md](../SECURITY_AUDIT.md)에 Bandit `B615`로 추적 중).
- 저장소 위생 규칙은 향후 커밋에서 `/scratchpad/` 및 임시 `*.db-wal` / `*.db-shm` 파일을 제외합니다. 과거 검증 토큰이 외부 환경에서 유효한 자격 증명이었던 적이 있다면 별도로 로테이션하세요.
