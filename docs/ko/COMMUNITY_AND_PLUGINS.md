# 커뮤니티 및 플러그인 가이드

현재 릴리스: **13.7.2 — Living Synthesis**.

LatticeAI는 탄탄한 로컬 우선 프레임워크(8.4.0 액션 인식 기반, 8.5.0 레지스트리+DI 강화, 8.6.0 캡처/탐색 안정화, 8.7.0 런타임 상태 정돈, 8.8.0 Brain Core 분리 준비, 8.9.0 스코프 기반 Tool API 강화, 9.0.0 정리 마감, 9.1.0 fail-closed 검토 완료, 9.2.0 모델 무관 파일 생성, 9.3.0 능동적 Brain 인텔리전스, 9.4.0 질문 기반 일상 자동화, 9.5.0 Command Center, 9.6.0 Trusted Agent Loop)에서 제품 생태계로 나아가는 길을 정의합니다. 당장의 목표는 작고 실용적입니다. 기여자가 로컬 우선 신뢰, 워크스페이스 스코핑, 릴리스 품질을 훼손하지 않으면서 Brain을 확장하는 방법을 분명하게 안내하는 것입니다.

## 커뮤니티 시작점

- 제품 문서부터 시작하세요: `README.md`, `docs/ko/WHY_LATTICE.md`, `docs/ko/ONBOARDING.md`.
- 로컬 개발 환경 설정, 검증, 릴리스 게이트는 `docs/ko/DEVELOPMENT.md`를 참고하세요.
- 플러그인 매니페스트, 호환성, 권한, 라이프사이클 상태, 카탈로그 엔드포인트, 설치 흐름은 `docs/PLUGIN_SDK.md`를 참고하세요.
- 최소 동작 플러그인 예제는 `plugins/hello-world/plugin.json`을 참고하세요.

## 플러그인 설계 방향

플러그인은 한 번에 경계가 명확한 기능 하나를 추가해야 합니다.

- `IngestionPipeline` 경로를 그대로 따르는 새 수집 소스
- 워크스페이스 스코핑을 유지하는 그래프 인식 도구
- 필요한 권한을 명시적으로 선언하는 워크플로우 템플릿
- 로그와 감사 페이로드에 비밀 값을 남기지 않는 에디터/자동화 도우미
- 네트워크 접근 전에 명시적 옵트인을 요구하는 로컬 우선 연동

## 안전장치

- 어떤 플러그인도 ToolRegistry, 권한 모델, 감사 훅을 우회해서는 안 됩니다.
- 어떤 플러그인도 프로비넌스 없이 그래프 데이터를 기록해서는 안 됩니다.
- 어떤 플러그인도 클라우드 모델, 원격 레지스트리, 상시 네트워크 연결을 전제로 해서는 안 됩니다.
- 호환성 요구 사항은 `lattice_version`에 선언하고, 예제는 현재 호스트와 호환되는 값을 사용해야 합니다.

## 현재 생태계 과제

- `hello-world` 플러그인을 항상 유효하고 단순한 상태로 유지합니다.
- 실제 확장 seam을 검증할 때만 예제를 확장합니다.
- 플러그인 API를 안정화하기 전에 테스트를 먼저 추가합니다.
- 거창한 생태계 약속보다 첫 기여자가 유용한 플러그인 하나를 직접 만들 수 있도록 돕는 문서를 우선합니다.
