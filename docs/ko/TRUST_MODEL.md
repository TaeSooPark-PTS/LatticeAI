# Lattice AI 신뢰 모델

현재 릴리스: **14.2.0 — Temporal Synthesis**.

Lattice AI는 로컬 우선(local-first)으로 동작하며, 외부 통신을 명시적으로 다루고, 기능을 사용할 수 없을 때는 정직하게 그 상태를 알립니다.

## 기본값은 로컬

기본 설정에서 Lattice AI는 API를 `127.0.0.1`에만 바인딩하고, Brain 데이터를 로컬 데이터 디렉터리에 저장하며, 프롬프트·문서·그래프 내용·아카이브를 Lattice 소유 서버로 전송하지 않습니다.

로컬 데이터에는 다음 항목이 포함될 수 있습니다.

- 프로필 및 세션 메타데이터
- 대화, 기억, 결정 사항, 워크플로우 실행 기록
- Knowledge Graph 노드, 엣지, 프로비넌스, 인덱스
- 업로드된 문서 원본 블롭 및 추출 텍스트
- 감사(audit) 및 관리자 작업 로그
- 백업 및 암호화된 `.latticebrain` 아카이브

## 명시적인 외부 통신 경로

외부 통신은 설정과 사용자 또는 관리자의 명시적 동작이 모두 있어야만 발생합니다.

- 자격 증명이 확인되고(`cloud_provider.json` / 환경 변수 키 / 로컬에서 OAuth 인증된 `agy` 또는 `grok`) 에스컬레이션 정책 또는 명시적 `/cloud` 접두사가 사용될 때의 클라우드 모델 호출. 이러한 모든 턴은 내용 없이 형태 정보(제공업체 / 모델 / 사유)만 남기는 송신 감사 로그를 기록하며, 추출된 지식은 Review Center 제안으로 스테이징됩니다.
- 설치 동의 이후 레지스트리에서 모델을 다운로드하는 경우
- `/setup/install`을 통한 패키지 설치(`brew` / `pip` / `uv`) — 요청에 명시된 항목이 **서버가 산출한** 허용 목록에도 포함되어 있을 때만 실행되며, 실제 명령어는 요청이 아니라 서버 자체 계획에서 가져옵니다. 기본 경로는 여전히 수동 설치입니다.
- Telegram 브리지 — 11.6.0에서 AI 워커로 전환된 플랫폼 코드와 함께 제거되었으며, 이를 대체하는 경로는 없습니다.
- 페어링 이후의 Brain Network 피어 동작
- 확장 설정에 옵트인한 뒤의 Docker/Postgres 구성
- 명시적으로 활성화한 경우의 업데이트 확인
- 명시적으로 호출한 경우의 마켓플레이스 또는 원격 레지스트리 새로고침

토큰이 존재한다는 이유만으로 외부 통신이 시작되어서는 안 됩니다.

인증된 대화 기록, Knowledge Graph 읽기, Tool API 호출 역시 호출자의 사용자/워크스페이스 범위 안에 머물러야 합니다. 직접 호출되는 HTTP/MCP 도구 라우트는 훅이나 핸들러가 실행되기 전에 ToolRegistry 정책을 먼저 적용합니다.

## 동의 및 정직성 게이트

Lattice AI는 다음 상황에서 fail-closed로 동작하거나 사용 불가 상태를 명확히 표시해야 합니다.

- 로드된 모델이 없는 경우
- 로컬 모델이 설치되지 않았거나 로드되지 않은 경우
- 클라우드 API 키가 누락된 경우
- 모델 없이 동작하는 결정적 미리보기인 경우
- 드라이런(dry-run)과 실제 실행의 구분
- 그래프나 컨텍스트 근거가 없는 경우
- 외부 연동을 사용할 수 없는 경우
- Knowledge Graph 워크스페이스 스코프를 알 수 없거나 읽을 수 없는 경우
- Telegram 인바운드 요청(브릿지는 11.6.0에서 제거되었으며 대체 기능 없음)
- 아카이브 암호(passphrase)가 틀린 경우
- 아카이브 변조, 지원하지 않는 아카이브 버전, 또는 경로 탈출(path traversal)이 감지된 경우
- 실제 임베더 대신 해시 폴백 임베더가 동작하는 경우 — `fallback`으로 명확히 표기하며 의미 검색으로 포장하지 않습니다.
- 옵트인한 근사 벡터 인덱스가 응답하지 못하는 경우 — 더 짧은 목록을 반환하지 않고 사유와 함께 정확 스캔(exact scan)으로 폴백합니다.
- 모델이 도구 호출을 생성하지 못하는 경우 — 동일한 게이트 아래에서 번호 선택지로 안내하며, 검증할 수 없는 결과는 여전히 `NEEDS_REVIEW`로 처리합니다.
- 지식 삭제 — 디스크에서 사라진 파일은 보고만 하며, 사용자가 삭제 정리를 확정한 경우에만 서브트리를 제거합니다.

## 제품 경계

일반 Brain 사용 영역은 대화, 기억, 주제, 관계, 모델 상태, 출처 수집, Knowledge Graph 탐색입니다. Admin Console은 사용자, 역할, 감사 로그, 보안 이벤트, 보관 정책, 운영을 담당합니다. 관리자 가시성이 비밀 값을 평문으로 노출해도 된다는 뜻은 아닙니다.

## 알려진 한계

- 로컬 파일의 보호 수준은 사용자의 기기, OS 계정, 백업 관리, 디스크 암호화 수준에 따릅니다.
- 사용자가 특정 클라우드 제공업체를 명시적으로 선택하거나(`cloud_allowed` 아래 `auto`/`always` 에스컬레이션 정책이 작동할 때) 전송되는 프롬프트는 해당 제공업체의 정책을 따릅니다. `api_key` 경로는 `GET /models`로 프로브하며(과금되는 completion 호출 없음), 실제 OAuth 경로는 과금 없는 `cli_oauth`를 사용합니다. 클라우드에서 추출된 지식은 제안 우선(proposal-first)으로 반영됩니다.
- 로컬 관리자는 Lattice AI 외부에서 로컬 파일과 프로세스 메모리를 검사할 수 있습니다.
- 마켓플레이스와 모델 레지스트리는 명시적으로 접속할 때 통신하는 제3자 서비스입니다.
