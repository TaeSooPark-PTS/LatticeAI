# 모델 정책

Lattice AI는 v9.6.0부터 멀티모달 우선(multimodal-first) 모델 정책을 적용합니다. 지속적인 제품 표면은 Brain이며, 모델 선택은 출처 사실, 기억 증빙, 모델 연속성 증거를 유지한 채 교체할 수 있는 실행 엔진입니다.

## 추천 규칙

- 현세대 멀티모달 모델만 추천합니다.
- 텍스트 전용 로컬 모델은 기본 추천 대상에서 제외합니다.
- 같은 패밀리에 더 새로운 세대가 있으면 하위 호환 폴백용으로 구세대를 유지하지 않습니다.
- 저사양 장비에는 소형 또는 양자화 멀티모달 모델을 사용합니다.
- 각 추천 사유를 쉬운 언어로 설명합니다.
- 모델을 사용하기 전에 출처 사실(Source Facts)을 먼저 표시합니다.

## 출처 사실 (Source Facts)

추천되는 모든 모델은 다음 5개 항목을 아래 순서대로 공개해야 합니다.

1. 제작 국가
2. 제작 회사
3. 실행 방식
4. 인터넷 사용 여부
5. 모델명

## 현재 모델 패밀리

- Gemma 4 (E2B / E4B / 12B / 26B A4B / 31B)
- Qwen3.6 (27B dense, 35B A3B MoE)
- Qwen3.5 (9B)
- GPT-OSS (20B, 텍스트 전용)
- LFM2.5 (2.6B, 텍스트 전용, 다국어)

텍스트 전용 패밀리가 포함된 이유는 두 가지 RAM 티어에서 필요하기 때문입니다. LFM2.5는 8GB 환경에서 쾌적하게 실행되는 유일한 항목이며, GPT-OSS 20B는 카탈로그에서 가장 많이 다운로드되는 모델입니다. 각 항목은 자신의 모달리티를 명시하므로 이미지 인식이 불가능한 모델을 "이미지를 읽을 수 있다"고 암시하지 않습니다.

## 현재 추천 카탈로그에서 제외된 모델

- Gemma 2 및 Gemma 3 (Gemma 3 저장소는 gated 상태)
- Qwen2.5-VL 및 Qwen3-VL
- Llama 3.x 및 Llama 4 (Meta 저장소는 gated 상태)
- Pixtral (vLLM 전용, `config.json` 미공개)
- Phi Vision 및 Moondream2 (두 저장소 모두 **Hub에서 삭제됨**)
- SmolLM, DeepSeek

## 단일 목록이 아닌 두 개의 목록

모델은 *제안되는(offered)* 상태와 *인식만 되는(understood)* 상태로 나뉩니다.

- **Recommended (추천)** — 현세대 모델. 카탈로그, RAM 티어, 다운로드 경로에 표시됩니다.
- **Recognised (인식)** — 후속 세대로 대체되었으나 실제로 존재하고 여전히 로드 가능한 모델. 절대 제안되거나 추천되지 않지만, 사용자가 이미 다운로드한 가중치가 알 수 없는 파일 덩어리로 보이지 않도록 이름·크기·런타임 프로필을 레지스트리에 보존합니다.

Hub에 더 이상 존재하지 않거나 다운로드에 인증 정보가 필요한 모델은 두 목록 모두에서 삭제합니다. 누구도 받을 수 없는 모델을 계속 인식 목록에 남기는 것은 호환성이 아니라 노이즈이기 때문입니다.

이 정책으로 기존 사용자 데이터가 삭제되지는 않습니다. 새 사용자가 구세대와 신세대 모델 사이에서 혼란을 겪지 않도록 현재 추천 표면만 정리합니다.

## 검증

`scripts/verify_hf_model_registry.py`는 공개 Hugging Face API를 기준으로 모든 항목의 존재 여부, gated 여부, 정규 대소문자, `library_name`/태그, 설정 아키텍처, 형제 파일 목록 및 정확한 바이트 합계를 재측정합니다. 이 스크립트는 **절대 가중치를 다운로드하거나 모델을 로드하지 않으며**, 그렇게 동작하는 플래그도 존재하지 않습니다.

따라서 이 스크립트의 로드 가능성 판정은 *정적(static)* 검증입니다(MLX 라이브러리 시그널 + `mlx-lm` / `mlx-vlm` 로더가 지원하는 config 아키텍처 + 커뮤니티 다운로드 수). 이는 "저장소 공개 메타데이터상 로드를 막는 요소가 없다"는 뜻이지 "실제로 로드되었다"는 보장은 아닙니다. 모델이 실제로 동작하는지에 대한 최종 판단 기준은 로더와 온디바이스 스모크 테스트입니다.
