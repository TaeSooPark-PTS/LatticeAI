# v11.5.2 — Tight Ship (설계 계획서)

안정화된 v11.5.1 트리를 대상으로 세 가지 감사가 실행되었습니다: AUDIT-A(Rust↔Python 중복 맵), AUDIT-B(100% 라인+브랜치 게이트에 대해 아크 수준까지 검증된 죽은 코드 및 더 이상 필요하지 않은 테스트), AUDIT-C(라이브 정문 패리티: Rust 게이트웨이 대 직접 연결된 Python 워커, 192개 엔드포인트 전수 스윕 및 표적 검증 배터리). 이 문서는 그 설계 종합본이며 구현은 두 번의 웨이브로 위임되었습니다. 이 릴리스의 어떤 변경도 마이그레이션의 최종 형태를 바꾸지 않습니다. 당시 기준으로 Python은 AI Worker이자 `/api/*` 라우트 구현으로 남아 있었고 Rust 표면은 패리티 골든으로 고정되었습니다.

## 릴리스 방향을 결정한 감사 판정

1. **경계 간(Cross-boundary) 중복은 모두 의도된 설계입니다.** 모든 Rust 모듈의 Python 쌍둥이는 Python 직접 모드에서 라이브 라우트를 제공하거나 패리티 골든을 공급합니다. 경계 간 삭제는 0건입니다. 실제 정리 대상 중복은 Python 내부와 Rust 내부에 존재합니다.
2. **죽은 코드는 Rust 이전 시점의 부채입니다.** 비테스트 임포터가 0개인 이동된 모듈 심(shim) 6개, 한 번도 연결되지 않은 스트리밍 경계 1개, 그리고 자신의 테스트 외에는 호출자가 전혀 없는 심볼 27개("테스트를 입고 있는 죽은 코드" — 구조상 커버리지 게이트에 보이지 않음)가 확인되었습니다.
3. **183개의 `test_cov_wp*` 파일은 모두 하중을 지탱하는(load-bearing) 테스트입니다.** 라인 분석만으로는 10개가 삭제 가능해 보이지만 이들은 합쳐서 79개의 브랜치 아크를 단독으로 커버하고 있습니다. 커버리지상 중복되는 7개의 기능 테스트 파일은 동작 회귀 검증 가치를 지니므로 의도적으로 유지합니다.
4. **정문(Front door)에는 일곱 가지 실제 격차(G1~G7)가 존재하며**, 그중 하나(프록시된 리다이렉트에서 `Set-Cookie`가 유실되는 현상)는 초대 게이트를 막다른 길로 만들고 SSO 로그인을 조용히 깨뜨립니다.

## 워크스트림 1 — 삭제 (쌍 단위, 게이트 보존)

- 이동된 모듈 심 6개 삭제: `latticeai/core/{graph_curator,hooks,multi_agent,workflow_engine}.py`, `latticeai/services/{ingestion,kg_portability}.py` + 심 존재 여부 테스트 + `[tool.mypy] files` 엔트리.
- `latticeai/services/multimodal_streaming.py` 삭제(연결된 적 없음; 향후 제공자가 추가되면 git 이력에서 복원 가능).
- AUDIT-B가 찾아낸 27개의 죽은 심볼 중 25개 삭제 및 `fail_under = 100`(라인 및 브랜치 아크)이 유지되도록 부수적 테스트 라인 정밀 정리. 검토된 3개 항목에 대한 결정: `delete_conversation`은 **유지**(공개 스토어 API이며 읽기 동치성 스위트에서 픽스처로 사용됨), `propose_file_delete`는 더 이상 생성될 수 없는 `approve()`의 `file_delete` 분기와 **함께 제거**, `multimodal_status`는 삭제하지 않고 **라우트에 연결**(워크스트림 3 — `FEATURE_STATUS`가 이미 사용자 대면 동작으로 문서화함).
- 벡터 인덱스 ABC에 선언되고 4번 구현되었으나 호출 횟수가 0번인 `metadata_for` 인터페이스 메서드를 ABC와 4개 구현체에서 모두 제거.
- 어떤 릴리스 아티팩트나 워크플로에서도 참조되지 않음을 확인한 후 `scripts/measure_brain_home_fill.mjs`, `tests/fixtures/filegen/`(읽히지 않는 데이터 파일 12개), 레거시 `desktop/electron/` 셸(포트 4825 하드코딩, 안전 플래그 미주입, Tauri로 대체됨) 제거.
- 레거시 심 게이트를 내부까지 확장하여 `latticeai/` 아래에 `sys.modules[__name__] = _impl` 형태의 심이 다시는 생겨나지 못하도록 차단.

## 워크스트림 2 — 통합 (명시된 경우를 제외하고 동작 보존)

Python(`lattice_brain`이 `latticeai`를 절대 임포트하지 않는 단방향 규칙 유지):

- **임베더 쌍 통합**: `latticeai/core/local_embeddings.py`는 골든으로 고정된 `lattice_brain/embeddings.py`와 바이트 단위로 동일합니다. 고정되지 않은 복사본을 삭제하고 임포터를 재연결하여 두 쓰기 경로 간에 벡터가 조용히 달라지는 실패 모드를 제거합니다.
- **`workspace_scope_from_request` 단일화**: 4개의 중복 재구현(`chat_helpers`, `upload_service`, `computer_use`, `admin`)이 모두 표준 `api/workspace_scope.py`를 임포트하도록 통합합니다. 의도된 동작 변경: 복사본들은 불일치 시 헤더를 조용히 우선했으나 표준 규칙은 불일치 시 `403`을 반환합니다.
- `_default_data_dir` ×4 → `core/config.py`; sha256-hex ×6 → 단일 헬퍼; SSE 프레임 빌더 ×5 → 바이트 단위로 동일한 단일 `sse_frame`; `model_runtime/engines.py` 위임자/죽은 조각 정리; AST가 동일한 모드 서비스 3종 → `JsonBackedModeService` 베이스 클래스; 모듈 임포트 가능 여부 검사 ×4 → 단일 헬퍼; `parse_iso` → `lattice_brain/utils`(골든 고정본); `_detect_gpu`/`_detect_cpu` → `setup/wizard/detect.py`.

Rust: `gateway/clock.rs`(전체 복사본)를 삭제하고 `lattice_retrieval::routes::naive_local_now`를 사용; `brain_not_found` 공유; `haystack`/`json_opt`를 `shape.rs`로 승격; `lattice-agent` 내부에서 `in_set`/`bad_request` 공통화; `is_py_space`/`round3`를 `lattice-core`에서 `lattice-ingest`로 공유. `lattice-agent`의 독립적인 `pystr`는 무의존성 격리라는 의도된 경계를 위해 그대로 유지합니다.

패치 릴리스에서 의도적으로 하지 **않은** 작업: 3개의 대형 라우트 팩토리(`create_workspace_router` 706줄 등) 분할 — 조용히 누락하지 않고 향후 과제로 명시적 기록.

## 워크스트림 3 — 정문(Front-door) 및 기능 격차 해소

- **G1/G4 (리다이렉트)**: 프록시가 리다이렉트 자동 추적이 비활성화된 전용 `reqwest` 클라이언트를 사용하도록 변경합니다. `3xx` 응답이 `Set-Cookie`와 `Location` 헤더를 온전히 유지한 채 그대로 통과하며, 내부 워커 오리진을 가리키는 절대 `Location` 값은 요청이 들어온 게이트웨이 오리진으로 재작성됩니다. 이를 통해 초대 게이트, SSO 로그인, 12개의 레거시 딥링크가 모두 정상 작동합니다.
- **G2/G3 (네이티브 레인 인증)**: 네이티브 `/rust/*` 및 `/host/*` 레인이 Python의 `trusted_local_owner` 보안 태세(posture)를 정확히 미러링합니다. 워커의 헬스 페이로드가 태세 정보를 포함하고, 게이트웨이는 기존 헬스 폴링에서 이를 캐시하며 **실패 시 닫힙니다**(태세를 알 수 없으면 네이티브 레인 거부). `LATTICEAI_REQUIRE_AUTH=true`일 때 네이티브 레인은 인증 없이 그래프를 제공하거나(G2) 루프 중간에 401로 죽는(G3) 대신 기계 판독 가능한 사유와 함께 즉시 `401`을 응답합니다.
- **G5/G7 (프록시된 신원)**: 프록시가 `X-Forwarded-For/Proto/Host`를 추가하고, 워커는 직접 연결된 피어가 루프백이거나 `LATTICEAI_TRUSTED_PROXIES`에 포함된 경우에만 `X-Forwarded-Host`로부터 유효 외부 오리진을 계산합니다. CSRF의 `Origin == Host` 폴백과 세 곳의 절대 URL 생성기(관리자 초대 링크, 권한 알림, SSO 리다이렉트 기본값)가 이를 사용합니다.
- **G6 (CORS)**: 슈퍼바이저가 CSRF 주입과 동일하게 게이트웨이 오리진을 담은 `LATTICEAI_CORS_ALLOWED_ORIGINS`를 주입하여 브라우저 확장과 교차 출처 로컬 클라이언트가 정문을 통해 정상 작동하도록 합니다.
- **감사에서 드러난 기능 격차 해소**: `graph_search`에 누락되었던 라우트(`POST /api/search/graph`) 연결, `multimodal_status`를 `FEATURE_STATUS`가 설명하는 라우트에 연결, `recent_chat` 컨텍스트 경계 조사 및 정렬, 라이브 `/agent` 핫패스 쌍둥이인 `tools/documents.py`와 `core/agent_profiles.py`를 픽스처 생성기에 편입.
- 작지만 정직한 수정: 두 CSP에서 오래된 `ws://` 제거(WebSocket 엔드포인트는 존재하지 않음), 게이트웨이 바인딩 실패 시 Tauri 셸이 죽은 오리진으로 이동하지 않도록 수정.

수정하지 않고 사유와 함께 기록한 항목: 프록시 홉의 일괄 요청 타임아웃 미적용(일괄 타임아웃은 장기 SSE 스트림과 15분짜리 모델 엔드포인트를 끊어버림), `request.is_disconnected()`가 게이트웨이 소켓을 바라보는 현상(프록시 구조 본연의 특성), 루프백에서 IP별 버킷이 하나로 합쳐지는 현상(게이트웨이는 루프백 전용이며 직접 연결 토폴로지도 동일하게 동작함).

## 릴리스 절차 요약

안정화된 트리(개발 3.14 + 클린 3.11)에서 두 웨이브를 모두 검증한 후 11.5.2 버전 상향(`Cargo.lock` 동기화 포함), OpenAPI 재생성(신규 라우트 반영), 릴리스 테마 "Tight Ship", `OPERATIONS` 제목, `screen-claims` 엔트리, 릴리스 노트 / `CHANGELOG` / `README` / 확장 `README`, 11.5.2 스크린샷 및 GIF 재촬영, `ARCHITECTURE` 시스템 맵 라벨 업데이트(프록시 시맨틱, 태세 게이트 네이티브 레인), `release:artifacts`를 통한 DMG 생성, 태그 및 GitHub Release, `main` 푸시, CI 그린 확인까지 완료합니다.
