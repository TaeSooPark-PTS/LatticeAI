## Why Incremental (Honesty Principle)

The existing Python platform sits on 44 router files, ~448 routes, and a 40,488-statement 100.00% coverage floor. Rewriting everything in a single release is incompatible with keeping the entire system unbroken. Each release therefore expands the set of **working, proven Rust slices** while Python converges into the AI Worker (model inference). 11.4.0 lays the foundation.

## Phase 1 Scope (11.4.0)

Introduce a new `rust/` Cargo workspace — 3 crates, all Tauri-independent (testable on Ubuntu CI with no desktop system packages):

### 1. `lattice-core` — Brain Storage Read Layer + Embedding Math

- Data directory resolution: `LATTICEAI_DATA_DIR` → default `~/.ltcai`, database `knowledge_graph.sqlite` (same file as Python).
- Read-only SQLite connection (`rusqlite` with `bundled` + **required `fts5`**): WAL mode, explicit `busy_timeout` (Python leaves it unset — Rust yields).
- Schema readers: `kgv2_nodes`/`kgv2_edges` views (lexical/graph lane), `nodes`/`chunks`/`vector_embeddings` (vector lane), `nodes_v2` (workspace scoping) — reproducing Python's per-lane table split verbatim.
- Embeddings module = 1:1 port of `lattice_brain/embeddings.py`: tokenizer (`[a-z0-9][a-z0-9_.:/+-]{1,}` + Latin 3-grams for len≥5 + Korean 2-grams for len≥3), Blake2b-8 hashed bag-of-features (low-bit sign), L2 normalization, `<f32` little-endian encoding/decoding (4B/dim, headerless), cosine similarity via **pure dot product** (dimension mismatch is a hard error). Default dim 384, model ID `lattice-local-hash-v1:{dim}`.

### 2. `lattice-retrieval` — Native Hybrid Search (with Parity Proof)

Parity targets **graph-layer `KnowledgeGraphStore.hybrid_search`** (2-channel alpha fusion) and its component lanes `search()` (keyword) and `vector_search()` (vector). Service-layer 3-channel fusion (`SearchService`) depends heavily on traverse/relationship queries and is explicitly deferred to Phase 2.

Under the default env configuration (`brute` backend, RRF/graph expansion/image fusion/CE rerank disabled), reproduce the following exactly:

- **Keyword lane**: trigram FTS5 `MATCH '"..."'` (doubled internal `"`, len<3 → empty) → LIKE fallback (`%q%`, `updated_at DESC, id ASC`) → topic-term backfill (`limit*3`) → **`(hits, type_boost, updated_at)` re-scoring** (`hits` = case-insensitive substring match count across 12 topic candidates, fixed `type_boost` set) + **2-pass stable sort (`id ASC` → `score DESC`)**. Caller-side score is `1/rank`.
- **Vector lane**: `embedding_model+dim` filter, `indexed_at DESC` candidate cap (default 10,000, `LATTICEAI_VECTOR_MAX_CANDIDATES`), sequential `f64` dot product (same accumulation order as Python → bit-exact), `min_score` filter, stable `(score, updated_at) DESC` sort, identical recall/honesty fields.
- **Policy**: `classify_query` (Korean/English regexes, priority `code → recency → person → fact`) runs on the **original query**; rewrite (whitespace collapse + 3 filler rules, remainder ≥ 4) runs on the search query. Only the `recency` class applies 14-day half-life decay `0.5 + 0.5*recency`.
- **Fusion**: lexical `1/rank`, vector max-normalization, `alpha*vec + (1-α)*lex`, `round(x, 6)` (**banker's rounding** — matching CPython `round`), sort `(-score, node_id)`, identity rerank (`rerank_score = score`, `top_k` cut), and isomorphic JSON fields/labels (`fusion`, `sources`, `policy`, `vector.*`).
- **Scoping**: `allowed_workspaces = None` ⇒ unscoped (local trusted owner default path) — do not change to fail-closed. Empty set ⇒ matches nothing. Legacy-global (`NULL`) is included only when `include_legacy_global` is set.

**Parity Harness (Bidirectional Contract)**:
- `scripts/generate_rust_parity_fixtures.py` (Python) builds a compact store through the real Python write path and commits `rust/fixtures/parity_store.sqlite` + query suite (Korean/English, 4 classes, len<3, zero hits, exact ties) + `rust/fixtures/golden/*.json` (Python engine outputs for hybrid/keyword/vector).
- `tests/unit/test_rust_parity_contract.py`: continuously re-runs the Python engine against the committed fixture DB and asserts golden equality — preventing Python semantic drift from silently invalidating goldens.
- `lattice-retrieval` cargo tests: assert Rust outputs == the same goldens on the same DB and queries. Scores match exactly by default (1e-12 tolerance allowed only on documented tie edge cases).

### 3. `lattice-host` — Supervisor + IPC/API Gateway

- **Supervisor (lib + bin)**: spawns the Python worker (preserving current Tauri resolution order: `LATTICEAI_DESKTOP_BACKEND_CMD` → `ltcai` → Python candidates → bundle tree; fixing the bug where `sort()+dedup()` broke priority), **`/health` HTTP probing** (replacing TCP connect probes), exponential backoff auto-restart on crash (bounded, respecting manual stop), graceful shutdown (`SIGTERM` → grace → `SIGKILL`), and **unified port selection**: scans from default 4825 for a free port and supplies the chosen port as the single source of truth to worker env (`LATTICEAI_PORT`) and Tauri (`backend_origin`). Logs continue to `~/.ltcai/desktop-sidecar.log`.
- **Gateway (axum, `127.0.0.1` only)**: `/host/health` and `/host/status` (supervisor status), native `/rust/search/{hybrid,keyword,vector}` (direct to `lattice-retrieval`, read-only), and reverse proxy for all other paths (preserving streaming/SSE). In Phase 1 this is an **opt-in front door** (when running the `lattice-host` binary) — existing entrypoints (`ltcai` CLI, direct browser access) remain intact. Non-loopback binds are rejected.

### 4. Tauri Integration (DMG Rides on the New Foundation)

`src-tauri` consumes `lattice-host` as a path dependency, replacing `main.rs`'s ad-hoc spawn/probe/restart logic with crate calls (451 lines → thin shell). The five frontend Tauri commands (`backend_origin`, `backend_status`, `restart_backend`, `shutdown_backend`, `select_folder`) and network topology (webview still loads `{origin}/app`) remain unchanged — users see higher supervisor reliability (HTTP health checks, auto-restart, port collision handling) with zero visible regressions.

### 5. Gates / CI / Versioning

- Add a `rust` job to `ci.yml`: Ubuntu, pinned stable toolchain, `cargo fmt --check` + `clippy -D warnings` + `cargo test` for `rust/` workspace only (no Tauri system deps). `src-tauri` builds remain in the macOS release workflow.
- Add `*.rs` to `check_max_file_lines.mjs` (1,000-line ceiling, excluding `src-tauri/gen` and `target`); target ≤500 lines for all new Rust files.
- Wire `rust/Cargo.toml` (`workspace.package.version`, crates use `version.workspace = true`) into `scripts/bump_version.py` and `test_version_consistency.py` to keep a single version source of truth.
- Python coverage floor (100% statement/branch) and frontend 100% stay unchanged. Rust is gated by cargo tests + parity goldens.

### Explicit Non-Goals (Deferred Beyond Phase 1)

- Native 3-channel `SearchService.hybrid_search` and KG read APIs (Phase 2),
- Ingestion (Watch/Parse/Chunk/Dedup) and Jobs/Events/Scheduler (Phase 2–3),
- Rust Agent Runtime (Tools/Sandbox/Permission) (Phase 4),
- Promoting the gateway to default front door (after e2e verification in Phase 2),
- HNSW/quantized backends, CE rerank, and image late-fusion parity (brute default path only; advanced modes proxy to the worker with zero feature loss).
